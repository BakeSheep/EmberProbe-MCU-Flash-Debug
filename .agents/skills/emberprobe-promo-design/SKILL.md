# EmberProbe 宣传图

本项目专用 skill。工作目录为 EmberProbe 仓库根目录；这是开发用的项目级技能，不属于 `skills/` 中随扩展分发的 MCU 操作技能。

## 内容与默认表达

- 从 `package.json`、目标版本的 `CHANGELOG.md` 和相关 `docs/` 核对事实；用户明确指定的文案优先。历史图只能作为设计参考，不作为新版兼容性或性能证据。
- 版本更新图默认采用品牌、版本、产品定位、“本次更新”、“同步优化”这些有实际内容的层级。每个重点功能使用一个标题加一句短描述，通常一行即可；次要优化用短语。
- 保留必要的“实验性”“估计”等限定，不把 mockup 数值表述为硬件实测。不要从“可选择多种探针”自行推导为“多探针同时连接”；并行能力按当前实现或用户确认表达。
- 默认不加更新梗概、空泛口号、截图说明、装饰性序号、英文眉题、日期或 MIT 开源页脚。用户要求增加这些内容时再加入。
- 写作与构图时阅读 [设计规则与本项目参考](references/design-rules.md)。按当前任务精简内容，不为了填满空白补文字。

## 截图与构图

- 需要新界面素材时，阅读 [mockup 截图](references/mockup-capture.md)，在浏览器中展示当前版本的真实 webview，默认使用白色主题并重新截图。不要复用旧版宣传图里的截图。
- 以画面中要证明的字段决定截图数量与裁切范围。截图保持比例；原生高密度渲染比放大已导出的位图清晰。
- 布局由内容决定。图文分栏、错落叠放、主图配局部、标题上置或竖向构图都可使用，不限定必须两张图、左图右文或固定坐标。
- 本系列横版参考常将文案集中在右侧，截图以大小差异、错位、轻微倾斜和适量重叠形成主次。让截图组合周围留出完整空白，避免两张等宽大卡片上下排满左半边。
- 重叠只遮辅助边缘，保留实验性标签、CPU 读数、枚举名称与数值等关键证据。小幅调整已有作品时保留已认可的构图，不顺手增加新装饰。

## 制作、验收与交付

- 默认横版为 3840 × 2160，预览宽约 1600；其他画幅重新组织内容。用独立 HTML/CSS 和原始截图制作，使用 CSS 变量集中管理尺寸、字体、颜色、间距和变换。
- 在 `promo/` 中保存可编辑 HTML、必要素材、高清 PNG、预览和检查报告。图片可内嵌，使 HTML 离线可复现。不要用生图模型绘制软件界面或文字。
- 标记 `data-promo-stage`、独立叶节点 `data-promo-copy` 和关键界面保护区 `data-promo-safe`。按 [渲染与验收](references/rendering.md) 使用本 skill 的 `scripts/render-promo.cjs` 导出并修复几何问题。
- 查看实际预览，再检查关键界面细节。资源、文字边界、层级、留白、截图完整性都通过后交付；自动报告通过不能代替看图。
- 最终展示预览，链接高清 PNG 与 HTML。仅改宣传素材时不修改扩展功能或 README，也不进行硬件操作或发布。
