# 本系列的设计规则

这些是本项目的默认偏好，用户当次要求可以覆盖。继承文案层级、留白与截图真实性，而不是固定坐标或有限模板。

## 先看参考，再处理新内容

| 参考                                          | 值得迁移的判断                                                    | 不应机械照搬                           |
| --------------------------------------------- | ----------------------------------------------------------------- | -------------------------------------- |
| [0.8.0 版本更新](examples/emberprobe-080.png) | 截图大小不同、错位与轻微倾斜；组合周围空白完整；标题配一句描述    | 三张截图、截图所含旧版本功能、具体位置 |
| [0.8.2 最终版](examples/emberprobe-082.png)   | 白色高清 mockup；两张图形成对角关系；文案在右侧；无日期或开源页脚 | 两张图、CPU / 枚举素材、四个功能条目   |

0.8.0 的灵动来自主次、错位、层次与周围空间，不能简化为“多加几张图”。0.8.2 的改进也不只是倾斜截图：先缩小整体占用、删掉冗长说明，再调整截图关系。

## 文案尺度

版本更新默认写法为“功能标题 + 一句短描述”。一句描述应补充具体对象或用途，而不是把更新日志搬进海报。例如本次认可的表达：

| 标题                   | 一句描述                                 |
| ---------------------- | ---------------------------------------- |
| CPU 负载采样（实验性） | FreeRTOS 工作负载估计 · 独占探针         |
| 枚举读数更直观         | C/C++ 枚举名称与数值 · 侧栏 / Live Watch |
| 多探针同时连接支持     | CMSIS-DAP / DAPLink / ST-Link            |
| Agent 操作先确认       | 烧录、写入与 CubeMX 生成前人工确认       |

这组内容是 0.8.2 的项目参考，后续版本重新核对事实和用户要求，不自动沿用。“同步优化”可以使用两列短语，如“调试与采样协调”“侧栏与波形同步”“ELF / SVD 解析优化”。

不要默认加入“连接更灵活，调试更从容”式梗概、“界面演示 / 示例数据”等画面说明、“01 / 02 / 03 / 04”、无信息的英文眉题，或日期、GitHub / MIT 页脚。mockup 的模拟属性记在源文件注释或交付说明中；用户需要画面内标注时再加入。

## 留白与阅读顺序

- 保持品牌、版本、栏目标题、功能标题、短描述的层级。“本次更新”“同步优化”需清楚可辨，不能缩成小注释。
- 先在目标预览尺寸检查行长。描述长时删减或改写，不连续缩小字体；不要使短描述成为两三行详情。
- 让标题周围、图文之间、截图组合外围和上下边缘保留可辨认的空白。不要让所有内容从顶边一直排到底边。
- 主要内容少时，缩小整体占用并让组合位于画面中部，避免用放大截图或标题填空白。也不为了某个“留白百分比”把内容缩成难读的小点。
- 文字在同一列内形成清楚的对齐关系，组间距离大于组内距离。没有需求时无需把每项功能包成独立卡片。

## 截图关系

先比较两种适合素材比例的构图，再选一种制作。例如：一张主要界面配一张倾斜辅助图，或宽截图与较窄截图错位组合。多图不必同尺寸、同高度、同倾角或等距排列。

本次使用小幅平面旋转形成层次；参考角度约 3° 与 −6°，只是起点。复杂数据表、数值和代码以清晰可读为先，不为灵动而施加强透视。阴影柔和、边框细、圆角浅，避免厚重悬浮窗口。

关键区域始终完整。CPU 采样图保留“实验性功能”、工作负载及覆盖率；枚举图保留变量名、枚举名和数值。允许辅助边缘重叠；不得遮住用于证明功能的字段，也不要重绘或改写截图中的读数。

## 配色与参数

系列常用白色界面、很浅的灰蓝或灰绿色背景、深色主文字、灰蓝次文字，以及少量暖棕色栏目强调。可从 `#171a20`、`#637082`、`#9c6c51` 起步；相应参数集中在 CSS 变量中。具体字体、间距与截图尺寸随画幅调整，不依赖此台电脑的绝对路径。
