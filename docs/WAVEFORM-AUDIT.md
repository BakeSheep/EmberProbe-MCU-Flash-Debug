# 波形历史与长时间采样审计

审计日期：2026-10-06。验证环境：Windows x64、Node.js 24.13.1；无探针、无实板操作。

## 清空历史后导出 CSV

原实现存在问题：`renderer.js` 的 `clearHistory()` 只清空浏览器中的实时缓冲和冻结快照；默认导出来源为扩展端 `SamplingArchive`，清空按钮没有通知归档服务。因此清空后选择默认“完整采样归档”仍可能导出清空前的数据。

修复采用每个归档 scope 的递增代次。显式清空只重置当前图表窗口、当前调试会话的归档元数据；新采样写入新代次，归档导出和 Agent CSV 读取均排除旧代次。其他窗口和其他调试会话不受影响。切换调试会话只清空图表视图，不删除目标会话已有归档。

同时清除该窗口待发送的标量、复合变量批次及最新值缓存；浏览器在收到清空确认前丢弃在途采样消息，旧代次的归档信息回复不能重新填入导出选项。清空同时关闭已打开的导出对话框并释放冻结快照。

清空是逻辑重置：旧记录仍占用临时归档磁盘预算，扩展退出时删除。清空不会重置归档容量上限，也不会撤回清空前已经开始的 CSV 导出。

## 200 Hz 采样 20 分钟后的卡顿

每通道约 240,000 个原始采样点。原实现收到新数据就失效绘图缓存；每次刷新都扫描、分段全部保留历史，随后再扫描统计，最后才提取可见区间。全历史视图还会为每个原始点分配 Canvas 几何对象，再按像素缩减绘制点。暂停采样后缓存不再持续失效，与用户报告的恢复流畅现象吻合。

修复先同步视口，用二分搜索定位可见区间及两端相邻点，再直接从原始数据按像素列保留首尾和最小／最大值，最后创建 Canvas 几何对象。失败采样仍分割曲线；相同近似 Number 的 64 位整数通过精确文本比较极值；采样点数统计仍显示原始有效点数量。实时缓冲、冻结快照和 CSV 都保留原始采样数据。

以下结果来自同一台机器的 JSDOM Canvas stub 基准。每个场景预填历史，反复使缓存失效，测量完整 `draw()` 路径；每个视图预热 8 次、统计后续 30 次刷新。它包含 JavaScript 数据处理和 DOM 操作，不包含真实 Canvas 绘制，不能视为浏览器帧率或实板结果。

| 场景 | 修复前中位耗时 | 修复后中位耗时 | 修复后 P95 |
| --- | ---: | ---: | ---: |
| 3 通道，最近 30 秒 | 131.2 ms | 9.3 ms | 11.6 ms |
| 3 通道，全部 20 分钟 | 715.0 ms | 27.4 ms | 30.7 ms |
| 10 通道，最近 30 秒 | 未测 | 24.2 ms | 26.2 ms |
| 10 通道，全部 20 分钟 | 未测 | 99.5 ms | 104.9 ms |

3 通道全历史的几何点由 720,003 个降至约 10,505 个；包含实时数据和绘图缓存的堆占用由约 118 MiB 降至约 53 MiB。

仍有边界：全历史视图需要遍历可见的原始点计算像素极值，10 通道场景的模拟耗时仍超过当前 80 ms 刷新间隔；大量失败采样产生的断点也需要保留。冻结复制全部原始历史，会增加瞬时开销和内存占用。实际 VS Code Webview 的 Canvas、GPU、窗口宽度和真实变量数量应在用户的采样环境中验证。
