# probe-rs 采样性能实测

2026-10-11，Windows x64，使用用户的 J-Link 与 `F407_car` 项目，经已有 Agent Bridge 切换性能后端并重新建立采样连接。测试复用当前监视计划：1 条波形变量和 1 个写入卡片监视变量，均为 4 字节 RAM 标量，地址相隔 324 字节。芯片配置为 `STM32F407ZG`；本次没有进行芯片身份鉴定。

## 方法与结果

切换前，Bridge 状态快照显示设定 100 Hz、实际 6.42 Hz、每轮读取耗时 P95 为 155 ms。用户也报告设定 20 Hz 时约 6.4 Hz，增加设定频率没有改善。

每个测试频率设置后等待至少 4.5 秒，再每秒记录一次 `sampling.status`，共记录 6 次。表中实际频率是这 6 个滚动窗口值的中位数；窗口有重叠，不视为 6 次独立实验。

| 设定频率 | 实际频率中位数 | 实际频率范围 | 各窗口读取耗时 P95 |
| --- | --- | --- | --- |
| 20 Hz | 19.88 Hz | 19.85–19.93 Hz | 32–33 ms |
| 100 Hz | 29.17 Hz | 29.17–29.43 Hz | 33–37 ms |
| 200 Hz | 29.16 Hz | 28.96–29.44 Hz | 34–35 ms |

20 Hz 测量期间没有错过采样期限。高频设置仍受约 34 ms 的读取周期限制，不能达到 100/200 Hz；最高实际频率相对 6.42 Hz 基线提升约 4.5 倍。此结果不证明其他探针、变量数量或目标固件的频率，也不证明达到用户反馈的 OpenOCD 200 Hz 性能。

测试结束后已恢复原有 100 Hz 设置，采样继续运行，使用性能后端。测试中的用户变量访问为读取，没有复位、烧录、变量写入或 USB 驱动切换。重新建立 `attach` 连接及读取休眠核心仍遵循上游的临时停核行为。

## 已验证的优化

- 扩展将读取和分发耗时计入周期，并在运行期管理自己的 Windows 精细定时器。
- stdio 输入可唤醒后端的空闲等待，保留原核心及 RTT 轮询期限。仅添加唤醒的第一轮实测已达到约 19.9 Hz，100/200 Hz 下约 28.5 Hz。
- 后端独立管理 Windows 定时器精度。本次增加此项后读取耗时没有显著改善。
- J-Link 连接复用两个 USB 端点，保留原超时取消、响应收尾、短写检查和整包读取兼容处理。最终实测为上表所示。
- 本轮源码还将分散 RAM 读取分为最多 4 个请求的批次，取消或失败时收完在途响应。这项由软件及 Extension Host 回归验证；本次真机窗口沿用已有扩展安装，未将新增分组代码计入真机性能结论。
