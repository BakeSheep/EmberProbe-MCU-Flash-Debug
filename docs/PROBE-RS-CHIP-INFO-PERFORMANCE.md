# probe-rs 芯片读取性能

普通运行态独立读取保留 CLI 路径，按用户选择优先减少运行干扰。没有为了加速而建立运行态 DAP 连接，也没有将旧芯片身份缓存作为新的硬件读取结果。

## 优化内容

- CPUID 完成后先向面板显示核心信息，随后补齐其他字段。读取结束之前禁用执行控制，结束后才写入完整缓存。
- Agent 字段与分组在读取之前生效。例如核心字段只读 CPUID，运行状态只读核心检查与 DHCSR，身份分组不读取运行状态和停机寄存器。ROM 指纹仍是 UID/容量读取的必要检查，Geehy/APM32 限制不变。选择性读取不覆盖面板缓存。
- F1/F2/F4 的 UID 与容量跨度为 20 字节，F7 为 36 字节，在一次连接中使用半字读取；跨度中的空洞不可读时回退到各字段。总字节与时间预算保持不变。
- 独立 Pause/Run/Reset 已经持有短连接 DAP；控制成功后的刷新复用该连接，不再为刷新重复启动 CLI 或 DAP。现有调试会话仍复用当前连接。

配置派生的探针类型、链路速度和协议等字段不需要内存读取。仅请求这些字段时，结果是配置元数据，不能据此判断探针或芯片在线。未知电压与探针版本仍不填入猜测值。

## F407_car 只读实测

2026-10-10，Windows，probe-rs 0.32.0，J-Link，工作区 `C:\Users\28951\Desktop\STM32Project\F407_car`。配置为 STM32F407ZG，ROM 指纹实际返回 Apex Microelectronics / Geehy APM32，因此 UID 和容量保持禁用。这块板不适用工厂信息合并优化。

先通过工程 Agent Bridge 确认没有调试和采样会话，再经服务和 `chipInfo` 租约读取。每个案例测量一次，CLI 进程之间也检查现有会话状态；结果包含这些检查的少量开销。未发送显式暂停、继续、复位、烧录或变量写入命令，也未运行完整 HIL。受限进程无法枚举 USB，测量使用常规本机权限。

| 读取内容 | CLI 连接次数 | 实测完成时间 |
| --- | ---: | ---: |
| 完整面板字段 | 4 | 2217 ms |
| 身份分组 | 3 | 1627 ms |
| 核心与 CPUID | 1 | 550 ms |
| 运行状态 | 2 | 1151 ms |

完整面板的首批核心结果在 556 ms 返回，完整内容仍约 2 秒。优化前通过工程 Bridge 测得完整读取 2034 ms；两次单次测量存在环境差异，不能将它们解释为完整读取吞吐提升。本次该板的改善是更早显示结果及减少按需读取的连接次数。

完整运行态刷新仍受多次 CLI 启动和 USB 连接开销限制。要大幅减少这一总耗时，需要可保持状态的批量读取接口；当前 DAP 初始化会暂停核心，因此本次没有改用该路径。

上游 CLI 本身也有状态副作用：[read 实现](https://github.com/probe-rs/probe-rs/blob/v0.32.0/probe-rs-tools/src/bin/probe-rs/cmd/read.rs)结束时调用 `resume_all_cores`，[Session 实现](https://github.com/probe-rs/probe-rs/blob/v0.32.0/probe-rs/src/session.rs)在连接和清理时处理断点。因此独立 CLI 不能承诺完全不停机或保持已暂停的原停止位置；需要保持断点状态时应复用已有 DAP 会话。
