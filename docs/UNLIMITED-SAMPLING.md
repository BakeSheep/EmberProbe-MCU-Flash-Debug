# 不限速采样

波形窗口的采样帧率支持手动输入 0.1–200 Hz，输入框内的下拉按钮可打开预设滑条，提供 20、50、100、200 Hz 四个挡位。
滑条最右端是「不限速」挡位，选择后输入框显示 `-`，滑条呈现从右向左铺开的紫色渐变。原实验性设置 `emberprobe.experimental.unlimitedSampling.enabled` 已移除，不再需要开启；用户设置中残留的该项不起作用。
拖动超过相邻挡位的中点后，滑块和色条同步切换到下一挡，输入框即时预览；松手提交一次配置，取消则恢复原值。`Hz` 显示在输入框外。滑块在轨道两端保留相同内边距，并垂直居中；不限速不会改变输入框的边框或底色。
不限速使用大范围柔和融合的蓝紫渐变，圆形波纹从右端内侧中心向外扩散，宽光晕缓慢流动，波动保持低对比度，不包含散点或密集色块。
仅在下拉面板可见时绘制，限制为 30 帧/秒及最多 384×64 像素；减少动态效果设置下使用静态画面。
不限速状态按工作区保存。选择有限帧率挡位或输入数值可退出不限速；调试会话中仍使用最近的有限目标帧率，原因可在输入框提示中查看。

## Scatter reads

Windows/Linux x64 默认使用[内置 scatter 补丁版 OpenOCD](../native/openocd/README.md)。`emberprobe.openocdPath` 保持默认 `openocd` 即可离线准备并使用；已指定外部或旧版手动安装绝对路径的用户可恢复默认值以使用内置版本，扩展不会覆盖这些路径。重连后自动探测 `emberprobe_read_scatter version`。支持时把一轮固定地址读取按最多 64 段 / 4096 字节合成尽量少的请求，每个请求仅调用一次 `dap_run()`；运行时对象（指针目标、STL 容器）按上一轮实际读取的地址用一次 scatter 请求预读并从中取值，只有对象移动后缺少的块单独读取，结束时的描述字复查也合并为一次请求；预读计入每轮 4096 字节 / 32 次读取预算，预读作废并超出预算时该对象不用预读重读一次。调试预算和代次保护保持不变。目标在连接时尚未完成检查（examine）时命令会拒绝，首次完整成功的采样轮后会再探测一次。`stats().scatterReads` 表示当前状态。

内置版本基于 xPack 0.12.0-7 使用的上游源码及 EmberProbe 补丁构建，并非官方 xPack 二进制。外部 OpenOCD 命令缺失或探测失败时使用原批量路径；采样命令失败或响应格式错误时当轮重读，目标不支持或连续三轮失败则在本会话禁用 scatter。采样连接超时仍按原连接故障处理。此处的单次 flush 不保证只有一个底层 USB/网络包。2026-10-24 原型的只读实板对比（16 个分散变量、不限速 10 秒）：APM32F407 + J-Link 由 191 Hz 升至 394 Hz，STM32H750 + CMSIS-DAP v1（HID）由 30.6 Hz 升至 81.0 Hz；这是原型的历史结果，不代替新构建资源的硬件验证。其他探针、无线链路及 Linux 主机尚未测量。

## 行为

| 项目         | 不限速开启时                                                                                  |
| ------------ | --------------------------------------------------------------------------------------------- |
| 适用会话     | 独立 OpenOCD 采样。调试会话（托管 OpenOCD + GDB 或 DAP 快照）保持原有自适应预算与目标频率     |
| 波形变量     | 每轮读取完成后立即开始下一轮（`setImmediate`），没有 5 ms 间隔下限，不做自适应降速            |
| 侧栏变量     | 仍为固定 20 Hz，与波形变量同轮到期时合并读取                                                  |
| 实际频率     | 由探针、USB、OpenOCD Tcl 往返和读取合并结果决定；工具栏显示「不限速 · 实际 N Hz」             |
| 限制因素     | `limitedBy: "probe"` 或 `"host"`；最近 1 秒内因宿主未及时消费而暂停的时间 ≥ 20% 时为 `"host"` |
| 配置与 Agent | `sampleFrequencyHz` 仍为 0.1–200 Hz；Agent Bridge 采样接口仍只接受 5–10000 ms，无法开启不限速 |

不限速不会改变读取计划、读取预算、写入授权或探针所有权。状态对象新增 `unlimited`、`unlimitedActive`、`unlimitedSuppressedReason`、`limitedBy`、`hostHoldMs`，`effectiveIntervalMs` 为 0。

采样过程中切换挡位会立即重排下一轮读取，不等待工作区配置写入完成。仅修改频率或不限速状态时保留已有读取耗时估计；已有足够耗时样本时，退出不限速不会重新从 100 ms 预热。独立模式按最近周期的平均耗时与 85% 占用率调度；调试模式仍按 P95 / 40%。预热、降速、恢复及切挡均使用同一统计量，`p95DurationMs` 与错过截止时间计数保持原定义，不限速仍不做自适应降速。波形实际频率在切挡后重新统计，收到两个新挡位的采样点即可计算，不再混入旧挡位的历史频率。更改监视变量或重新启动采样仍需要预热。

## Tcl 响应与合并读取

样本时间使用 Worker 内 `performance.timeOrigin + performance.now()`，保留 Unix epoch 的小数毫秒。每轮的全部样本（含运行时对象与失败诊断）共用本轮首次读取前到末次读取后的中点，不按读取组拆分，保持每轮一行归档/CSV；周期不重叠，同一通道时间严格递增（侧栏复用仍保留原时间）。调试守卫及截止时间继续使用 `Date.now()`。历史、Float64 归档及 CSV 保留小数时间；整数毫秒的 CSV 文本不变，亚毫秒时间多输出 3 位微秒。

间隙合并后，非 4 字节对齐或长度非 4 倍数的固定读取组，可向外扩至完整 32 位字范围；仅当完整扩读范围位于同一可写且已分配 ELF 节内，并且不超出调试字节/命令预算时生效，随后再次合并相邻组。未知范围、跨节、Flash 与外设不扩读；额外字节只计吞吐与预算，不交付变量，写入方式不变。独立采样可用 `emberprobe.samplingAdapterSpeedKhz` 单独指定链路时钟，`0` 沿用通用时钟，详见 [J-Link 连接设置](JLINK-COMPATIBILITY.md)。

独立与托管调试会话在 Tcl 连接完成后、任何采样或普通命令之前，最多用 500 ms 自测 `return -code exit` 响应：要求 socket 精确返回随机标记，再用普通回显标记同步日志，确认前一标记没有出现在日志中。通过后直接传送 `EP_OK:` / `EP_ERR:`，省去 OpenOCD 的逐字符日志回显与调试模式的临时文件往返。自测失败沿用原方式；socket 回复正确但收不到日志同步时，独立模式可启用，调试模式保留临时文件，避免无法排除的 GDB 广播。超时或断开的自测连接先丢弃并重连，迟到响应不会进入采样 FIFO。标记及纯 `EP_OK:` 回显不进入诊断尾部；错误处理保持原样。

以下为内置 xPack OpenOCD 0.12.0+dev-02228、Windows、`adapter driver dummy` + `noinit` 的单次 RPC 测量，不代表实板频率：

| 每次 RPC | 原方式（µs） | 无回显（µs） |
| --- | ---: | ---: |
| 32 words | 309 | 53 |
| 256 words（1 KB） | 2132 | 52 |
| 1024 words（4 KB） | 8373 | 63 |
| 调试临时文件（32 words） | 1243 | 53 |

宿主把 ELF 的可写且已分配节（`SHF_WRITE | SHF_ALLOC`）范围随采样计划传给 Worker，Worker 校验整数地址、32 位边界与范围数量。两个读取组间隙不超过 32 字节且完整跨度落在同一节内才合并；无节信息、跨节、外设或未知区域保持原方式。间隙字节只计入实际读取吞吐，不交付给变量；1024 字节 / 8 组分批、调试周期字节/命令/时间预算与运行时对象规则保持不变。

`npm run check:openocd-noecho`（或 `node scripts/check-openocd-noecho.js`）单独解包当前平台内置 OpenOCD 到 `test-results/`，仅用 dummy adapter 检查响应、无回显、普通回显与连接复用，不接触硬件，不属于普通测试组。更换内置 OpenOCD 时可单独运行，不能用软件检查代替实板验证。

## 连接仲裁

背靠背循环下，Tcl 连接空闲的窗口只有一个事件循环轮次。原先读写事务每 10 ms 轮询 `busy`，会被循环长期饿死。现在采样会话使用 FIFO 仲裁：

- 变量写入、单次读取、空闲等待按到达顺序排队；释放时所有权直接交给队首，采样轮次无法插队。
- 采样轮次只做非阻塞获取；有等待者时让出本轮。
- 超时仍返回 `PROBE_CONNECTION_BUSY_TIMEOUT`；停止或连接失败时立即拒绝排队者。

仲裁同样用于常规模式。

## 宿主流控

采样 Worker 每次向扩展宿主发送一个有上限的分片（≤256 批或约 256 KiB）并等待确认，其余批次留在 Worker 内排队。不限速时，若最早未送达的批次已排队 100 ms，或积压达到 1 MiB / 1024 批，Worker 暂停发起新的变量读取，积压送完后立即恢复，期间时间计入 `hostHoldMs`。固定频率采样不受宿主确认影响，详见 [LAYERED-SAMPLING.md](LAYERED-SAMPLING.md#数据流与竞态) 的积压预算。图表批次和逐样本时间戳保持原样；只有尚未送达的侧栏独有批次会合并为每个变量的最新值。

## 历史与归档

- 历史 Worker 的近期内存缓存每变量最多保留 360,001 点，且不超过 30 分钟。例如 2 kHz 的内存约覆盖 3 分钟；更早的点由磁盘归档提供，图表仍可查看从采样开始或上次清空以来的整个会话，预算计算与常规模式相同。
- 无历史 Worker 的回退路径同样按每变量 360,001 点裁剪。
- 磁盘归档以 `EPSA` v1 小端二进制日志 `samples.bin` 完整记录每批数据，通道键/身份字典只写一次，数值仅在文本精确往返时压缩。稳定字典下 1 / 3 / 10 个 f32 通道约 28 / 42 / 91 字节/行；默认 1 GiB 上限包含文件头和字典，耗尽后与常规模式一样报错并暂停采样。采样中工具栏的速率旁会在剩余不足 1 小时时显示「归档剩 mm:ss」（按最近约 10 秒的写入速度估算），剩余约 10 分钟与 1 分钟时各在状态栏提示一次；`emberprobe.samplingArchiveMaxMiB` 修改立即生效，调高后提示重新计时，已写满停止的采样也可重新开始（调低不会删除已写数据）。每约 64 KiB 的内存时间索引和字典快照让恢复从最近 30 分钟附近开始，再按完整记录边界追赶；CSV 继续读取完整归档，字段与输出格式不变。
- 绘图刷新仍为约 12.5 次/秒（80 ms 节流），视口数据按像素列缩减并以类型化数组传输，与采样频率无关；请求、超采样与底图见 [LAYERED-SAMPLING.md](LAYERED-SAMPLING.md)。

### 完整会话查看

完整会话查看由 Worker 的归档 LOD 索引支持：256 点 L0、每 16 桶一级，索引预算为内存历史配置的 25%
（默认 128 MiB）。长范围和底图使用摘要，放大旧范围时按需读原始行（每请求 16 MiB 上限，8 MiB 解码缓存）。
预算不足时最旧 L0 退为更粗摘要；`limited` 表示内存和归档均无法提供的数据，内存淘汰和索引变粗本身不再触发此标记。
冻结同时固定时间和归档字节截点，清空切换代次；“全部”、时间轴和底图覆盖全会话。实现、边界测试和 2/8 小时软件基准见
[完整会话历史](plans/2026-10-22-long-history.md)。无历史 Worker 的回退路径仍受原内存上限约束。

## 实板采样对比

2026-10-24 在 Windows 11 上只读测量（`scripts/measure-sampling-scatter.js`，不烧录、不写内存、不复位/暂停），每项 10 秒，SWD 使用目标脚本默认时钟。“基线”为 P0 之前的 `af2efc5` 代码 + 官方 xPack OpenOCD 0.12.0-7；“P0+P1”为当前代码 + 同一 OpenOCD；“+补丁 OpenOCD”再换用 [scatter 原型](../native/openocd/README.md)。单位 Hz，未标目标频率的行为不限速。

| 场景 | F407 + J-Link V9：基线 / P0+P1 / +补丁 | H750 + CMSIS-DAP v1（HID）：基线 / P0+P1 / +补丁 |
| --- | --- | --- |
| 16 个分散变量 | 186.7 / 193.4 / 396.9（2.1×） | 30.5 / 30.5 / 80.8（2.6×） |
| 32 个分散变量 | 93.0 / 96.3 / 217.4（2.3×） | 15.2 / 15.3 / 44.1（2.9×） |
| 16 个相邻字段（间隔 16 字节） | 185.6 / 308.9 / 307.9（1.7×） | 30.5 / 81.7 / 81.7（2.7×） |
| 1 KB 连续块 | 73.9 / 88.8 / 89.2 | 21.8 / 22.3 / 22.3 |
| 1 KB 块，采样时钟 8 MHz | — / — / 145.3（较基线 2.0×） | — / — / 37.6（较基线 1.7×） |
| 1 KB 块 + 16 个分散变量 | 52.5 / 60.7 / 75.0（1.4×） | 12.7 / 12.9 / 18.1（1.4×） |
| 16 个分散变量，目标 200 Hz | 102.4 / 137.5 / 192.4（1.9×） | 17.8 / 25.0 / 64.4（3.6×） |
| 1 KB 块 + 16 个分散变量，目标 100 Hz | 30.3 / 46.1 / 56.8（1.9×） | 8.6 / 9.7 / 14.9（1.7×） |

- 相邻变量由 P0 的间隙合并收益：每轮读取段数降为 1，补丁 OpenOCD 不再额外提速。分散变量的段数无法合并，主要由补丁 OpenOCD 的单次 flush 收益，变量越多倍数越大。
- 1 KB 块受 SWD 时钟和探针包大小限制：去掉回显在 J-Link 上每轮省约 2 ms，HID 探针上几乎看不出；提高采样链路时钟（`emberprobe.samplingAdapterSpeedKhz`）收益最大。
- 有目标频率时，基线的 P95 / 70% 自适应规则与截止时间漂移明显拉低实际频率；P0 的平均耗时 / 85% 与相位锁定已提升 1.1–1.5 倍，读取变快后 F407 基本达到 200 Hz 目标。
- 时钟行使用当前代码直接指定 8 MHz，等同设置采样链路时钟；APM32F407 上的 J-Link V9 由 OpenOCD 限制在 12 MHz 以内。无线 CMSIS-DAP、ST-Link、DAPLink v2 及 Linux 主机尚未测量。

## 宿主处理能力参考

`node test/perf/unlimited-host-bench.js` 测量单个波形窗口每批在扩展宿主主线程上的解码、二进制归档编码及 Worker 消息克隆开销，不含磁盘写入；另以预建 f32 文本行比较旧 NDJSON 和二进制编码的字节数与耗时。字节比较包含 13 位时间戳和 `bench` scope，不含身份，文件头/字典摊入 10,000 行。以下为 Windows 11 / Node 24 / Ryzen 7 H 255 的一次结果，仅用于判断宿主是否可能成为瓶颈：

|    3 |       18.0 |      约 5.5 万 |               0.7 |

| 通道 | NDJSON 字节/行 | 二进制字节/行 | 空间缩减 | NDJSON µs/行 | 二进制 µs/行 |
| ---: | -------------: | ------------: | -------: | -----------: | -----------: |

常见探针每轮读取为毫秒量级，实际频率通常远低于宿主上限；扩展宿主同时执行其他重任务时才可能出现 `limitedBy: "host"`。以上为软件测量，不代表实板吞吐；不同探针（ST-Link、CMSIS-DAP v1/v2、J-Link）的实际频率需在真实硬件上验证。
