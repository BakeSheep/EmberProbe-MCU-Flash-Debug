# 连续拖动写入滑条

用户反馈 probe-rs 自动采样时，拖动写入滑条反复出现“调试器操作进行中，请稍后写入”。侧栏按 100 ms 节流发送，但没有等待 `writeResult`，定时回调遇到前一笔写入的正常 busy 状态就丢弃最新值并显示错误；busy 状态同时禁用控件，打断拖动。

改为侧栏全局最多一笔写入在途，每个变量仅保留最新的待发送值。继续保留 10 Hz 拖动节流，收到写入结果且当前会话可写后发送最新值；释放滑条提交最终值，相同在途值不重复发送。旧回读结果不得覆盖用户更新的值。

当前侧栏写入引发的 writing/snapshot 状态允许继续编辑并安静等待。外部执行控制、停止采样、会话或停止代次变化、列表重绑定及真实错误清除待发送值。DAP 状态提供会话与停止代次，消息携带该上下文，后端在执行前拒绝旧上下文。失败后的请求不自动重发，所有写入继续经过原有类型、RAM 范围、会话身份与回读校验。

DOM 回归覆盖慢写入、密集拖动、最终值、多个变量、节流、旧结果、停止/切换/移除和真实失败。通过模拟 probe-rs 的 Extension Host 验证拖动写入与回读；执行全量 check、quality、bundle 和 E2E。本次不操作真实探针，不安装扩展、不改 README，保留既有未提交工作。

2026-10-10 Windows 验证完成：`npm run check` 396 个测试文件通过；`npm run quality` 的 lint、格式、类型检查、188 个覆盖率测试及安全模块门禁通过；`npm run test:e2e` 包含 bundle，Extension Host 回归通过。实际侧栏 DOM 的密集输入经生产消息处理器合并为 `55` 和最终值 `73` 两次模拟 DAP 写入，均经回读验证，busy 状态期间控件保持可用、反馈区无误报。真实探针上的拖动与写入尚未验证。
