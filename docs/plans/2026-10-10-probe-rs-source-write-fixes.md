# probe-rs 源码断点与自动采样写入修复

用户反馈：通过“开始采样”自动 attach 后，GCC C++ 源码断点未验证，写入仍提示需要开启采样。

只读检查确认 `app_main.cpp:171` 在当前 Debug ELF 的地址为 `0x08007fc2`，编译为 `-O0 -g3`。该编译单元使用 C++14 DWARF 标识，行表无 `prologue_end`；本机 probe-rs 提交 `48f5e4d` 的 prologue 补偿仅包含部分 C 语言。此外，VS Code 请求盘符小写，DWARF 为大写；上游绝对路径比较保留大小写。

保留上游断点解析。普通源码断点因行解析失败时，使用当前调试 ELF 的有预算 DWARF 行表解析，映射到实际可执行指令；经上游指令断点设置验证后才报告源码断点已验证。将各源码的回退地址与用户的指令断点合并，清除单一来源不影响其他来源。解析放在现有 ELF Worker 内，使用会话 ELF 身份检查，禁止高级断点静默回退。

自动 attach 的写入继续绑定当前采样会话、RAM/DWARF 类型与回读校验。快照刷新的短暂窗口应等待当前会话的读取结果，停止采样、执行状态变化或会话切换立即拒绝；不得额外连接探针或自动重发写入。界面分别提示采样未开启、快照读取中、写入中或后端不支持写入。

验证覆盖 GCC C++ 无 prologue 行表、Windows 路径大小写、无映射/损坏/超预算行表、混合源码与指令断点清理、自动采样入口和保存写入列表后的立即写入，以及停止/切换时无写入。运行受影响普通测试、全量 check、quality、bundle 和 Extension Host E2E。本次不接触硬件、不改用户 MCU 工程、不修改 README，并保留已有未提交改动。

2026-10-10 Windows 软件验证完成：`npm run check` 395 个测试文件通过；`npm run quality` 的 lint、格式、类型检查、187 个覆盖率测试及安全模块门禁通过；`npm run test:e2e` 包含最终 bundle，隔离的 VS Code Extension Host 回归通过。C++ 自动采样会话中的源码断点经真实 ELF Worker 回退、模拟 DAP 指令验证并命中，新增仅写入变量后的立即写入通过回读校验。测试使用工作区临时目录，无真实探针连接。

用户现有 Debug ELF 的只读离线解析与 `arm-none-eabi-gdb info line` 一致：`app_main.cpp` 第 171/172/173 行分别为 `0x08007fc2`、`0x08007fdc`、`0x08007fea`；空白第 175 行不映射。真实板卡的断点命中与 RAM 写入仍需单独验收。
