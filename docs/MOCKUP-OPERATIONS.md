# 网页演示的操作状态

网页演示复用扩展的真实侧栏和图表渲染器，并用 `mockup/mock/coordinator.js` 统一模拟探针所有权、调试状态和采样意图。侧栏按钮、命令面板和调试工具栏共享这些状态。

## 操作关系

| 当前状态            | 实时变量与图表                   | 变量写入       | RTOS / 外设                              | 其他探针操作                               |
| ------------------- | -------------------------------- | -------------- | ---------------------------------------- | ------------------------------------------ |
| 无调试、未采样      | 停止，可启动                     | 禁用           | 无调试快照                               | 可烧录、调试、读取芯片、切换驱动或测量 CPU |
| 独立采样            | 两路可同时运行                   | 侧栏采样时可写 | 无调试快照                               | 可烧录或启动调试；驱动切换和 CPU 测量禁用  |
| 烧录 / 调试启动     | 暂停读取，保留已有采样意图与历史 | 禁用           | 禁用                                     | 禁止重复或竞争操作                         |
| 调试暂停            | 使用 DAP 快照，数值保持稳定      | 侧栏采样时可写 | 可刷新暂停快照、读写允许写入的外设寄存器 | 禁止烧录、芯片控制、驱动切换和 CPU 测量    |
| 调试运行            | 单核场景下使用 OpenOCD 只读采样  | 禁用           | 禁用并失效旧暂停快照                     | 禁止竞争探针操作                           |
| CPU 测量 / 驱动切换 | 禁止新采样                       | 禁用           | 禁用                                     | 当前操作独占探针                           |

在 WinUSB 驱动下，以上所有状态均允许读取芯片信息。演示中的读取刷新当前模拟目标快照，不创建第二个探针会话，不暂停采样或改变调试状态、探针所有权及暂停代次。只有正在读取时禁用读取按钮，重复点击不会创建新任务；约 700 毫秒后用完成时的目标状态和时间刷新信息。暂停、继续和复位等芯片控制仍受操作互斥限制。该规则只修改网页模拟，不修改扩展的真实硬件服务或授权。

烧录约 4.8 秒，完成后重置模拟目标并恢复仍有意图的采样。用户在等待期间主动停止的采样不会自动恢复。启动调试约 2.2 秒，完成后暂停于 `main.c:103`；停止调试返回独立采样状态。

CPU 测量经历检查、约 10 秒的首个采集窗口，再每秒更新模拟负载和覆盖率。它与实时变量、图表、调试和其他占用探针的操作互斥，期间仍可刷新芯片信息。

SVD 下载不占用探针；取消会清除该任务的全部回调，保留此前配置，允许立即重试。销毁页面宿主会清理其采样、调试及后台任务，迟到的回调不能恢复旧任务。

每次继续、暂停、单步、复位和会话变化都会更新暂停代次。网页发出的变量写入、外设操作与 RTOS 刷新携带当前代次；旧代次的请求和写入回读会被丢弃。

## J-Link 驱动选择

MCU 配置默认展开，“选择调试器”右侧复用扩展真实的驱动下拉框和切换忙碌指示。默认驱动为 WinUSB。SEGGER 选项对应恢复此前备份的原驱动，不表示 EmberProbe 支持使用 SEGGER 驱动执行目标操作；真实驱动和备份要求见 [J-Link 兼容性](JLINK-COMPATIBILITY.md)。

切换模拟约 900 毫秒：恢复 SEGGER 时显示恢复状态，切回 WinUSB 时显示安装状态；完成前保持原来的确认值。无效值、重复的待处理请求及探针忙碌时的请求不会修改驱动。选择已确认的驱动不创建切换任务。采样、烧录、调试和 CPU 测量期间禁止切换驱动。

SEGGER 状态下显示需要 WinUSB 的提示，禁用烧录、调试、两路采样、CPU 测量、芯片信息刷新及芯片控制；直接发送这些命令也返回 `PROBE_DRIVER_UNSUPPORTED`。驱动选择仍可用，切回 WinUSB 后恢复操作入口。切换过程中若已开始的芯片刷新在 SEGGER 生效后才完成，丢弃该次读取结果。页面初始化重放当前确认值，销毁宿主取消尚未完成的切换。

演示不调用原生驱动助手，不弹出系统 UAC，也不改动电脑上的 USB 驱动。

## 支持范围

演示工程固定为 STM32F407ZGTx、J-Link 和 OpenOCD，数据不来自硬件。未实现的工程选择等命令明确返回演示范围提示。VS Code 外壳继续使用官方 Codicon、Seti 文件图标和 VS Code 标识；EmberProbe 品牌及扩展内的图标与扩展本身一致。

侧边栏固定显示 EmberProbe，其他活动栏入口禁用；启动调试也不会切换侧边栏。演示不创建或展示 `launch.json`，也不展示“运行和调试”的变量、监视及调用栈占位内容。调试工具栏、编辑器断点标记和控制台保留。内存数据基于固定 ELF / MAP 场景，省去“估计”徽标。

支持 F5 继续 / 启动、F6 暂停、F10 单步跳过、F11 单步调试、Shift+F11 跳出、Shift+F5 停止及 Ctrl+Shift+F5 重启。焦点位于侧栏或图表内时，调试和全局面板快捷键也会转发到外壳。三个单步动作均采用简化的下一可执行行推进，不解释 MCU 指令或真实调用栈。

## 操作输出

初始页面的终端、输出与调试控制台为空。按用户的实机界面反馈，演示的“输出”面板保持为空，不添加 EmberProbe 通道或内容。采样、CPU 测量、SVD 下载和芯片读取的状态只在侧栏与图表界面反馈。

烧录终端和调试控制台按操作阶段追加内容。日志随任务取消或页面销毁而停止，成功摘要只在任务完成后产生。同一终端保留连续烧录的历史，最多保存 2000 行。

| 操作 | 演示通道                  | 来源和行为                                                                                                                                                                                        |
| ---- | ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 烧录 | 终端 `EmberProbe OpenOCD` | `mockup/mock/operation-output.js` 在构建时调用 `src/openocdRunner.js` 的真实 `parseLine`；按真实的箭头和勾号格式输出适配器时钟、器件 ID、写入、校验、复位以及固件 / 芯片 / 探针 / 时钟 / 配置摘要 |
| 调试 | 调试控制台                | 参照 `src/debug/mi.js`、`src/debug/session.js` 转发的 GDB console 文本，模拟符号载入、远程连接、各 ELF 段载入、断点命中、继续、暂停、单步与脱离；每次启动清空上一个调试会话                       |

探针型号、2000 kHz 时钟、器件 ID 和工程路径由同一份演示连接数据生成，侧栏信息与日志一致。所有日志是模拟数据，没有执行日志中列出的 OpenOCD / GDB 命令。

## 验证

- `node test/mockup.test.js`：操作竞争、读写权限、暂停数据、过期请求、取消 / 重试和销毁清理回归。
- `npm run mockup`：从当前真实渲染器生成演示资源。
- `node mockup/smoke.js`：生成页面与静态资源完整性。
- `npm run check`、`npm run quality`、`npm run bundle`、`npm run test:e2e`：仓库软件检查与扩展宿主验证。

软件验证不建立实板兼容性；本次验证不操作探针、驱动或固件。
