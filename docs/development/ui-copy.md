# EmberProbe 界面文案规范

适用于插件的按钮、标签、状态、悬停提示、错误通知、确认弹窗和 VS Code 设置说明。

- **正式、自然。** 使用直接、专业的中文，避免口语缩写、随意比喻和生硬的技术直译。例如用「已安装」「达到上限」「阻塞」。
- **简短，先说重点。** 标签直接写动作或状态。提示优先说明当前情况、对用户的影响和下一步。能用一句话说清的内容就用一句，避免重复界面上已有的信息。
- **用用户能理解的语言说明功能。** 保留 ELF、RTT 等与当前任务直接相关的术语。内部协议、算法、分片和回退机制等细节，适合放在诊断详情或文档中。界面只保留能帮助用户理解状态、做出决定或完成操作的技术信息。
- **文案必须符合实际行为。** 核对提示的触发条件、恢复条件和可用操作。区分「正在启动」和「正在运行」、「暂时不可写」和「需要重新添加」。按钮和设置使用界面中的实际名称。对性能提升、自动恢复和写入结果，只描述实现能够确认的范围。
- **精简时保留关键风险。** 涉及写入、烧录、驱动切换或采样停止时，保留会影响用户决定的条件和后果。后台会自动恢复的状态，应写清恢复条件，避免让用户执行多余操作。

简短的悬停提示可以写「仅在独立采样时生效」。需要用户采取行动时，可以写「实时采样正在启动，请稍候再烧录。」
