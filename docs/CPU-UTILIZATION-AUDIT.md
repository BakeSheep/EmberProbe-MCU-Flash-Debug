# MCU CPU 占用率计算审计

审计日期：2026-10-07。范围：EmberProbe 当前实现，以及 Cortex-M/FreeRTOS 常见测量方法。
本报告是源码和公开资料审计，不代表芯片、探针或实板验收。混合只读采样已按本次方案实施，实板验收仍待完成。

## 实施更新

新增 `CpuLoadService`、采样 Worker 内的独立 CPU 消费者、纯分类与时间权重窗口、独立侧栏面板。
任务与异常共同决定“CPU 工作负载估计”，PC 仅增加热点；未知时间不重归一化，`ulRunTimeCounter` 保持原义。
所有采样寄存器只读，未使用 `profile`、DHCSR 轮询、halt/resume 回退或 Trace 开启操作。
后续用户要求自适应频率：200 Hz 改为请求上限，按实际计划槽计算覆盖率，主动降频与真正漏采分开；
低覆盖时隐藏主负载数值，提供已知工作占比和按时间权重计算的未知原因。
H7 兼容性检查改为按 OpenOCD 目标类型识别唯一 Cortex-M 核，允许辅助 `mem_ap` 访问目标；
CPU 读取绑定已验证的命名目标，实际多核和其他目标类型仍拒绝。H750 工程内核 ELF 元数据已离线验证，实板采样仍待验收。
前端已按用户要求分为“其他”下的内存占用与实验性功能两块，上方内存标题带刷新按钮，
下方实验性功能标题带播放／暂停采样按钮。CPU 圆角进度条只显示负载百分率与计算覆盖率；后台采样与统计口径不变。
以下“当前仓库的实际能力”保留审计前快照作为依据；新功能的实际范围与限制见 [CPU 工作负载监测](CPU-LOAD-MONITORING.md)。

## 结论

可以做到不修改固件、不增加目标端统计代码、不为了采样暂停 CPU，但需要目标提供可观测的信息。
普通 SWD/JTAG 可以后台读取已有运行计数或当前任务；部分芯片还支持硬件 PC 采样。
前两者可以提供计数统计或任务驻留估计，硬件 PC 采样可以提供执行热点估计。
要精细区分任务、中断、调度器和空闲时间，通常需要软件事件记录或具备时间信息的硬件追踪。

“零代码”“不暂停”和“完全零扰动”是不同承诺。后台读取仍使用调试链路和目标互连；
Trace 可能需要配置寄存器、引脚和时钟，调试连接也可能影响低功耗行为。
不能对所有 MCU、探针和低功耗模式保证完全零影响，也不存在通用的“CPU 占用率寄存器”。

## 先定义所测指标

对于长度为 `T` 的单核观测窗口，理想的互斥分类是：

```text
T = 任务执行 + ISR 执行 + 调度/内核执行 + 空闲/睡眠 + 未观测时间
有效工作负载 = (非空闲任务执行 + ISR 执行 + 归入工作的内核执行) / T
```

Idle 忙循环也消耗执行周期，但通常算作调度器空闲；因此“非 Idle 工作负载”与“非睡眠比例”不同。
裸机系统必须提供已知空闲路径或地址范围；硬件无法判断一个忙循环是等待还是有用计算。
多核需要分别报告每核结果，平均值必须按各核有效观测时间计算，不能直接相加当成单核百分比。

未观测时间必须单独报告。若分类互斥且已知工作时间为 `B`、未知时间为 `U`，
真实工作负载只能限定在 `B/T` 到 `(B+U)/T`，不能把未知时间默认为 Idle 或重新归一化后隐藏。

## 行业常见方法

| 方法 | 计算机制 | 不修改现有固件？ | 主要边界 |
| --- | --- | --- | --- |
| RTOS 运行统计 | 切换任务时累加时间，主机计算窗口增量 | 固件已经启用时可以 | 有统计开销；默认统计未独立分离 ISR |
| Idle Hook 计数 | 与空载基准比较 Idle 循环次数 | 通常不可以 | 需钩子；受优化、频率、缓存和睡眠影响 |
| 后台读取当前 TCB | 按采样命中次数估计各任务驻留比例 | 通常可以，需可解析的任务身份 | 是估计；ISR 期间当前 TCB 通常仍属于被打断任务 |
| 后台读取硬件 PCSR | PC 样本映射 ELF 函数和地址范围 | 支持该硬件功能时可以 | 无效样本、周期混叠、共享函数、睡眠行为和实现差异 |
| SWO/SWV 硬件事件 | 输出 DWT PC 样本、异常事件与时间信息 | 硬件事件可以；软件 ITM 输出仍需代码 | 需硬件、引脚、带宽、时钟及协议解码 |
| ETM 指令追踪 | 重建执行流，结合时间信息积分 | 可以 | 需芯片 Trace 能力、采集硬件及足够的时间信息 |
| SystemView 等软件事件记录 | 记录任务切换、ISR 进入/退出等事件 | 通常需固件集成；已集成可直接使用 | 目标端记录有开销，缓冲和丢包影响完整性 |

FreeRTOS 官方给出了运行统计开关和时间源要求；统计时间源由应用提供，与 RTOS tick 不同。
参见 [FreeRTOS 内核书第 12 章](https://github.com/FreeRTOS/FreeRTOS-Kernel-Book/blob/main/ch12.md)。

SEGGER J-Scope 的 HSS 通过后台读取变量工作，不需目标端插桩；RTT 采集则需要目标端提供数据。
这证明“无代码的数据采集”可行，但采集通道本身不会产生 CPU 负载语义。
参见 [J-Scope 官方说明](https://www.segger.com/products/debug-probes/j-link/tools/j-scope/)。

Keil 提供基于 ETM 的性能分析，不需源码插桩；其应用笔记明确区分统计 PC 采样和完整执行追踪。
参见 [Keil STM32F7 应用笔记](https://www.keil.com/appnotes/files/apnt_280_v2.0.pdf)。

SystemView 根据每个上下文在时间窗口内的活动时间计算负载，区分任务、ISR 和 Idle；
它通常需要目标端集成，不能把其“低开销”解释为“未插桩固件也能直接使用”。
参见 [SystemView 官方手册](https://doc.segger.com/UM08027_SystemView.html)。

## 不能忽略的计算问题

### 1. 累计运行计数必须转换为窗口增量

```text
任务 i 的窗口比例 = ΔC_i / ΔC_total
按默认任务记账得到的非 Idle 比例 = 1 − ΔC_idle / ΔC_total
```

分子、分母必须来自同一目标统计时间源，不能直接用主机毫秒数除以目标 cycles。
当前仓库没有取得可靠总时间源或补齐当前任务未结算片段，因此直接给现有 `runtime.counter` 加百分号不成立。

FreeRTOS V10.6.2 在切换任务时更新 TCB 计数，因此当前任务的最新执行片段可能尚未计入；
时间源继续运行而没有任务切换时，TCB 计数不一定同步增长。
ISR 时间通常落在被中断任务的记账区间内；Idle 被打断时，只计算 Idle 的补数会低估工作负载。
还需处理计数回绕、复位、任务删除、TCB 地址复用，以及跨字段读取的一致性。
存活任务计数之和不能无条件替代总时间。64 位计数通过多次总线读取时也需避免撕裂。
参见 [FreeRTOS V10.6.2 tasks.c](https://raw.githubusercontent.com/FreeRTOS/FreeRTOS-Kernel/V10.6.2/tasks.c)。

### 2. 当前任务采样可以零代码，但不能自动独立统计 ISR

运行中只读取已经确定地址的 `pxCurrentTCB`，按稳定任务身份汇总：

```text
任务驻留估计 = 命中该 TCB 的样本数 / 有效样本数
非 Idle 驻留估计 = 1 − 命中 Idle TCB 的样本数 / 有效样本数
```

这是基于上述内核行为提出的实现推断，尚无本项目实板验证。
不要每次遍历整个任务链表；身份解析与运行期采样应分开。
Idle 应依据已证明的任务身份识别，不能只看名称或优先级零，其他任务也可能使用同样名称/优先级。

例如：普通任务占 10%，ISR 在 Idle 期间占 60%，纯空闲占 30%。
只采样 TCB 可能看到 Idle 驻留 90%，显示非 Idle 10%；包含 ISR 的实际工作负载则是 70%。
即使增加异常状态读取，多寄存器读取也不是原子快照，必须控制转换期间的不一致误差。

### 3. PC 采样需要明确能力和无效状态

DWT 支持情况取决于具体实现，不能仅凭 Cortex-M 型号承诺 PCSR、计数器和 Trace 全部可用。
Arm 的 Cortex-M7 手册列出可选 DWT 功能和寄存器，支持硬件 PC 样本及异常事件。
参见 [Arm Cortex-M7 TRM，第 11 章](https://documentation-service.arm.com/static/5e906da3c8052b1608760e3d)。

不能把 `0xFFFFFFFF` 统一解释为睡眠：它还可能来自暂停、Trace 未启用、权限限制或没有可用地址。
参见 [Armv8-M 架构手册 DWT_PCSR](https://community.arm.com/cfs-file/__key/communityserver-discussions-components-files/471/DDI0553B_5F00_y_5F00_armv8m_5F00_arm.pdf)。

PC 不在 Idle 函数地址范围，也不一定意味着正在工作：Idle 可能调用钩子、睡眠函数或公共库函数。
不同任务也可能执行同一函数，所以函数热点不等于每任务占用率。
需要经过验证的 Idle 路径、异常信息和任务身份，无法分类的样本保留为 unknown。

固定采样周期可能与 tick、PWM 或周期任务同步。可采用抖动采样并报告实际采样率、窗口和覆盖率。
在独立、均匀二项样本的理想假设下，1000 个样本的最坏 95% 误差约为 ±3.1 个百分点；
相关样本或系统性漏采不满足这一保证。低采样率不能可靠证明短暂尖峰或单次 ISR 最大执行时间。

### 4. 不要直接复用 OpenOCD profile 命令

上游 `cortex_m_profiling()` 使用 PCSR；判断不支持时调用 `target_profiling_default()`。
后者会反复 halt/resume，前者也会恢复原本暂停的目标。
因此，需要独立的能力检查和有界寄存器读取，并在不支持时报告 unavailable，禁止静默侵入式回退。
这是上游源码结论，实际集成还需核对本项目所用 OpenOCD 二进制对应版本。
参见 [Cortex-M profiling 源码](https://openocd.org/doc/doxygen/html/cortex__m_8c_source.html)
和 [默认 profiling 源码](https://openocd.org/doc/doxygen/html/target_8c_source.html)。

### 5. CYCCNT、SLEEPCNT 不能单独解决通用负载统计

CYCCNT 是周期计数，不识别任务和 Idle；空闲忙循环也会增加周期数。
SLEEPCNT 测睡眠相关周期，并不测调度器空闲；常见 Cortex-M3/M4 的该字段只有 8 位，
毫秒级轮询可能漏掉多次回绕，无法单靠模 256 差值恢复经过时间。
EXCCNT 是异常开销计数，也不能直接当作 ISR 函数体总时间。
参见 [Arm CMSIS Cortex-M4 定义](https://raw.githubusercontent.com/ARM-software/CMSIS_5/develop/CMSIS/Core/Include/core_cm4.h)。

## 初始审计的实施建议

以下记录实施前的分阶段建议。当前首版已按本文开头的实施更新完成任务与异常混合采样；
运行计数窗口化、SWO/ETM 和多核支持仍属于后续范围：

1. 固件已有运行统计时，优先提供明确标注口径的窗口计数结果；未启用时保持 unavailable。
2. 严格要求无需重编译时，先做单核 FreeRTOS 当前任务后台采样，展示“任务驻留估计”，明确 ISR 未分离。
3. 经芯片能力验证后增加 PCSR/异常观测，提供执行热点与带覆盖率的工作负载估计；不得使用 halt/resume 回退。
4. 对精细任务/ISR 时间线，增加 SWO 硬件事件或带时间信息的 ETM 后端，另行验收资源占用与丢包。

运行期采样必须复用现有探针所有权，绑定所选 session/core、目标镜像和运行代次；
暂停、复位、会话切换或镜像改变时结束当前窗口。禁止为了统计恢复原本暂停的目标。
CoreSight 配置应通过独立受控服务保存、恢复；不能沿用普通变量写入来绕过寄存器策略。
Trace 模式应避免因采集拥塞让目标停顿；验证低功耗、时钟变化、缓存可见性和安全域权限。
共享组目前的运行期采样禁令应保留，直至专门完成多核路由和租约验证。

建议同时输出测量方法、指标定义、窗口长度、实际采样率、有效样本、未知比例、
ISR 是否独立统计、睡眠是否覆盖及丢包状态。显示精度应与证据匹配。

## 验证情况

初始审计检查了任务快照、RTOS 展示及后台读取边界，并核对上述官方资料和上游源码。
首版实现新增分类、时间权重、元数据、真实 Worker 通道、连接生命周期及界面测试；
“任务 10%、Idle 期间 ISR 60%、纯空闲 30%”的用例验证工作负载为 70%。
普通测试与质量门禁已通过，打包和 Extension Host 测试覆盖新增 Worker 接口及默认关闭行为。
侧栏另行检查了 320 像素中文和 420 像素英文布局。

这些软件测试不能证明实板精度或零扰动。初始实施未连接实板；随后按用户授权经 Agent Bridge
对 `F407_car` 做了 6 次只读 tick／调度器检查，确认目标调度器在运行，未修改固件或执行控制。
新自适应策略的实板覆盖率与百分比精度仍待单独运行验证；
具体使用口径、能力边界与后续实板验收要求见 [CPU 工作负载监测说明](CPU-LOAD-MONITORING.md)。

后续精度验收应覆盖：纯 Idle、纯计算、已知占空比、Idle 期间高 ISR 负载、tickless、
短周期任务、计数回绕、任务创建删除、调试暂停、采样丢失和多核。
真实负载参考需要独立时间证据，并记录测量前后目标时序与低功耗行为。
