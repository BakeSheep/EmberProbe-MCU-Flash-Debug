# 动态成员写入

现有 `variables.write` / MCP `variables_write` 接受带类型的动态标量路径，侧栏查看列表也共用定位流程。右键加入写入列表时，卡片保存当前样本的叶子地址、编码、宽度和布尔标记，重载后继续使用这组绑定。ELF 全部变量列表只允许通过静态路径添加已知可写成员，提交时也走静态计划。

查看列表写入卡片须有当前连接、ELF 和调试停止代次的有效样本，且样本须匹配加入时的绑定。失效时取消待提交的输入和滑块值。旧会话的写入进度可以显示在通知中，卡片值以当前会话的新样本为准。原绑定恢复后等待新样本重新启用。宿主在计划前后复核会话，在规划后再检查采样、查看列表成员资格和解析得到的叶子。已经进入传输队列的请求通过共享标志在独占事务内取消，最后一次检查发生在请求发送前。

## 定位与权限

`runtimeWritePlan` 复用 `RuntimeObjectReader` 的指针、动态类型和 libstdc++ 容器布局解释器。宿主根据请求中的路径、当前 ELF/DWARF 和实时内存确定写入地址、编码及描述信息。界面附带的绑定仅用于比较，内存传输使用宿主解析的地址。路径只选择单个标量，不执行 C++ 表达式、方法或容器修改操作。

侧栏菜单使用运行时样本附带的可写性判定。采样器和写入规划共享引用、派生类型、容器元素、类型限定及可写 RAM 范围规则。独立动态查看项保存路径，重新加载时从当前 ELF 恢复运行时读取计划。可能随活动成员改变编码的叶子进行独立读取，每次按样本中的实际类型解码。缺少活动标量时发送不可用样本。

根符号必须完整位于已分配 ELF 节中。根指针自身可以位于只读段，例如引用或常量指针；这里只读取它。最终叶子必须位于可写已分配节或 ELF 解析器已验证的 linker heap-stack 区。读描述信息仍受原有已分配区域约束；不会把外设区或任意地址加入写入范围。

类型图保留布尔编码、const 别名和枚举编码是否推断。写入遍历传播值成员的 const 属性；解引用时重新依据目标类型判断，因此 `T * const` 可以指向可变目标，`const T *` 的目标不可写。拒绝指针存储、成员指针、位域、身份不明的 union 成员、不完整类型和推断编码。STL 只能经语义元素入口访问；map 键、set 元素、内部指针/计数和字符串存储不开放。

数组必须有 DWARF 固定边界或受支持容器的实时有效范围；裸 `T *` 本身不提供分配长度。链表遍历和容器访问复用原有深度、字节和读次数预算。每批规划共享 4096 字节、32 次读取及可注入时钟控制的 1 秒期限；不读取完整对象来猜测布局。

## 计划与执行

准备阶段读取描述信息并重新核对其一致性，生成单个叶子的写入项和可序列化的 `runtimeChecks`（描述地址及原始字节）。计划绑定原有 ELF 哈希、连接身份、值和最终地址，并加入描述快照及所选调试会话/停止代次。Agent 确认往返期间不保持事务锁；再次请求会重新解析，描述、地址或停止代次改变后旧确认失效。已有工作区授权和完整访问模式保持原语义，但不跳过类型、身份、范围及执行期描述检查。

Tcl 与暂停 DAP 写入器在原有独占事务内检查描述快照：事务开始、每项写入前及读回后。验证工作有独立的 4096 字节/32 次读取上限，并在写入前验证整批预算及写入与描述区不重叠。检查数据可穿过采样 Worker；不把函数或界面缓存地址传给 Worker。动态 DAP 写入不合并相邻项，以保留逐项检查。暂停 DAP 事务在等待读取结束前捕获规划的停止代次，并在等待后及事务内继续核对。匿名成员查找同样拒绝穿过无法确认活动成员的 union；容器解释器仍可依据有效判别字段选择元素。

实际编码和内存写入继续复用 `agentPlans`、`MemoryWriter` 和现有 DAP 内存写入。托管调试运行中仍只允许自然对齐的 32 位写入；其他宽度要求暂停。动态写入标记随每个写入项传给 Tcl 和暂停 DAP。动态窄写只提交叶子本身的字节，读回不匹配时返回 `WRITE_VERIFY_FAILED`。这也适用于无需描述快照的 `std::array` 等目标。普通静态写入保留既有的窄写及对齐字回退。多字段写入不承诺原子性。出现 `WRITE_TARGET_CHANGED` 时报告已经写入的项数和未验证状态，不自动重发或回滚。侧栏同一变量的写入失败后，已经排队的后续滑块值同时中止，最新请求收到失败反馈；之后的新操作重新规划。传输超时或部分写入返回 `resultUnknown`；首项尚未确认时 `written` 为 null，而不是声称没有写入。事务整体也检查时限。

## 并发边界

描述复核能发现可观察到的指针重定向、容器搬迁及范围变化。运行中的固件仍可能在最后一次复核和实际写入之间移动目标，或释放后在同地址重用内存。实现沿用调试器的有效对象前提：调用方必须确保实例在事务期间有效。需要更强保证时暂停所有相关修改源，或由固件在所属任务中应用调参请求；宿主独占锁不能阻止其他核或 DMA 修改内存。读回匹配只证明当次读取的字节匹配，不证明控制算法已经采用新参数。

## 验证

单元测试覆盖指针链、数组边界、const 与布尔语义、禁止区、描述变化、预算和超时；集成测试覆盖既有 Agent 确认流程、Tcl/暂停 DAP 事务和部分写入状态。真实 ARM DWARF 4/5 fixture 检查 vector、list、deque、map 值、智能指针等布局的叶子定位，并拒绝 map 键、set、vector<bool> 和字符串。软件验证不能替代实板缓存一致性、对象生命周期及控制行为验证。

实现参考了 [Cortex-Debug 的 GDB 赋值流程](https://github.com/Marus/cortex-debug/blob/master/src/gdb.ts)、[mcu-debug 的实时写入协调](https://github.com/mcu-debug/mcu-debug/blob/main/packages/mcu-debug/src/adapter/live-watch-monitor.ts) 和 [Scrutiny 的指针变量定位](https://github.com/scrutinydebugger/scrutiny-main/blob/master/scrutiny/server/datastore/datastore_entry.py)。本实现独立编写，复用 EmberProbe 自有的类型解析、会话及授权，不复制上述项目代码。
