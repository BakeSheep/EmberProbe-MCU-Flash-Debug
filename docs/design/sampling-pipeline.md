# 采样链路设计

用户行为见[实时采样与历史](../guide/variables.md#实时采样与历史)，历史与归档见[波形历史与归档设计](chart-history.md)。

## 频率滑条

滑块拖过相邻挡位的中点后，滑块和色条同步切换，输入框即时预览；松手提交一次配置，取消恢复原值。滑块在轨道两端保留相同内边距并垂直居中；不限速不改变输入框的边框或底色。

不限速挡位使用大范围柔和融合的蓝紫渐变，圆形波纹从右端内侧中心向外扩散，宽光晕缓慢流动，保持低对比度，不包含散点或密集色块。动画仅在下拉面板可见时绘制，限制为 30 帧/秒及最多 384×64 像素；减少动态效果设置下使用静态画面。

## 分散地址读取（scatter）

Windows/Linux x64 默认使用[内置 scatter 补丁版 OpenOCD](../../native/openocd/README.md)。`emberprobe.openocdPath` 保持默认 `openocd` 即可离线准备并使用；已指定外部或旧版手动安装绝对路径的用户可恢复默认值以使用内置版本，扩展不会覆盖这些路径。重连后自动探测 `emberprobe_read_scatter version`。支持时把一轮固定地址读取按最多 64 段 / 4096 字节合成尽量少的请求，每个请求仅调用一次 `dap_run()`；运行时对象（指针目标、STL 容器）按上一轮实际读取的地址用一次 scatter 请求预读并从中取值，只有对象移动后缺少的块单独读取，结束时的描述字复查也合并为一次请求；预读计入每轮 4096 字节 / 32 次读取预算，预读作废并超出预算时该对象不用预读重读一次。调试预算和代次保护保持不变。目标在连接时尚未完成检查（examine）时命令会拒绝，首次完整成功的采样轮后会再探测一次。`stats().scatterReads` 表示当前状态。

内置版本基于 xPack 0.12.0-7 使用的上游源码及 EmberProbe 补丁构建，并非官方 xPack 二进制。外部 OpenOCD 命令缺失或探测失败时使用原批量路径；采样命令失败或响应格式错误时当轮重读，目标不支持或连续三轮失败则在本会话禁用 scatter。采样连接超时仍按原连接故障处理。此处的单次 flush 不保证只有一个底层 USB/网络包。

## 行为

| 项目         | 不限速开启时                                                                                  |
| ------------ | --------------------------------------------------------------------------------------------- |
| 适用会话     | 独立 OpenOCD 采样。调试会话（托管 OpenOCD + GDB 或 DAP 快照）保持原有自适应预算与目标频率     |
| 波形变量     | 每轮读取完成后立即开始下一轮（`setImmediate`），没有 5 ms 间隔下限，不做自适应降速            |
| 侧栏变量     | 仍为固定 20 Hz，与波形变量同轮到期时合并读取                                                  |
| 实际频率 | 由探针、传输和宿主消费速度共同决定，波形工具栏显示实际频率与吞吐，频率输入框显示 `-` |
| 限制因素     | `limitedBy: "probe"` 或 `"host"`；最近 1 秒内因宿主未及时消费而暂停的时间 ≥ 20% 时为 `"host"` |
| 配置与 Agent | `sampleFrequencyHz` 仍为 0.1–200 Hz；Agent Bridge 采样接口仍只接受 5–10000 ms，无法开启不限速 |

不限速不会改变读取计划、读取预算、写入授权或探针所有权。状态对象新增 `unlimited`、`unlimitedActive`、`unlimitedSuppressedReason`、`limitedBy`、`hostHoldMs`，`effectiveIntervalMs` 为 0。

采样频率按 `1000 / Hz` 换算为小数毫秒，Worker 用单调时钟推进截止时间。切挡时用已有的读取耗时估计安排下一轮，选频后用已验证档位的耗时确定首轮间隔。缺少有效测量时从 100 ms 预热。

独立限速采样用主要消费者的平均读取耗时和 85% 占用率计算所需间隔。有波形时仅记录波形事务的读耗时，侧栏预算单独计算。最近 32 轮全部成功时剔除一次最慢的读取。稳态评估至少间隔 500 ms 且需要新增至少 4 次有效测量，两次评估方向相同才调整周期。读取错误后的恢复冷却为 2 秒。调试模式用 P95 / 40% 及逐步恢复，不限速模式跳过间隔调优。用户切挡和波形读取计划变更会重新统计相应频率，自动调整周期时滚动窗口继续积累有效样本。

Windows 高精度定时器可用时先休眠，剩余时间至多 1.5 ms 时通过 `setImmediate` 让出事件循环直至截止。高精度定时器不可用时提前一个粗定时刻唤醒，最后至多 12 ms 主动等待。停止或重排时取消相应定时任务。

## Tcl 响应与合并读取

Tcl RPC 的超时以注入时钟的单调时间计算，不受系统时钟校正影响。超时仍丢弃整条无 ID 的 FIFO 连接，
不重放读取或写入；诊断保留命令类别（不含命令参数和写入值）、请求序号、预算、实耗时间、
是否已收到完整响应、残留字节数及距最近成功响应的时间，并附带有界 OpenOCD 日志尾部。
这些字段只能定位停顿被观察到的位置，不能独立证明无线丢包或探针断线。
收到 OpenOCD 明确的 CMSIS-DAP 通信错误日志（例如返回命令不匹配）时，会话报
`PROBE_COMMUNICATION_FAILED` 并结束。读取适配器响应失败的部分日志只在调试级别可见。
Tcl 回复和进程日志分开到达。收到 scatter 命令的 `scatter memory read failed (错误码)` 时，
立即结束本轮读取，避免日志稍后到达时已经触发普通读取。该回复单独按 Tcl 命令错误处理。
USB 后端启动时的短时清空也会记录 `USB timeout @ ...`，单条这类日志不触发断开。
如果 Tcl 超时先发生，当前请求报告 Tcl 超时。
会话内部选项 `scatterReads: false` 可用于关闭加速的诊断对照，不增加用户设置，
也不会在超时后自动切换读取路径或重新发送请求。
独立持续采样的 `sampling.status.lastDisconnect` 在连接清理后仍保留最近断开诊断；
它是历史记录，不表示当前会话仍失败。

Agent 有限采样把每轮读取耗时计入目标间隔，使用注入时钟的单调时间。
本轮已达到或超过间隔时直接进入下一轮，避免 `setTimeout(0)` 引入额外定时器等待；
实际读取仍通过 Worker 异步请求，停止和取消守卫保持生效。中途失败的诊断保留
`completedSamples`、`requestedSamples`、`lastSampleTimestamp`、请求间隔及来源，
这些进度信息不替代未返回的部分样本，也不代表已完成全部采集。

样本时间使用 Worker 内 `performance.timeOrigin + performance.now()`，保留 Unix epoch 的小数毫秒。每轮的全部样本（含运行时对象与失败诊断）共用本轮首次读取前到末次读取后的中点，不按读取组拆分，保持每轮一行归档/CSV；周期不重叠，同一通道时间严格递增（侧栏复用仍保留原时间）。调试守卫及截止时间继续使用 `Date.now()`。历史、Float64 归档及 CSV 保留小数时间；整数毫秒的 CSV 文本不变，亚毫秒时间多输出 3 位微秒。

间隙合并后，非 4 字节对齐或长度非 4 倍数的固定读取组，可向外扩至完整 32 位字范围；仅当完整扩读范围位于同一可写且已分配 ELF 节内，并且不超出调试字节/命令预算时生效，随后再次合并相邻组。未知范围、跨节、Flash 与外设不扩读；额外字节只计吞吐与预算，不交付变量，写入方式不变。独立采样可用 `emberprobe.samplingAdapterSpeedKhz` 单独指定链路时钟，`0` 沿用通用时钟，详见 [J-Link 连接设置](../guide/getting-started.md#j-link)。

独立与托管调试会话在 Tcl 连接完成后、任何采样或普通命令之前，最多用 500 ms 自测 `return -code exit` 响应：要求 socket 精确返回随机标记，再用普通回显标记同步日志，确认前一标记没有出现在日志中。通过后直接传送 `EP_OK:` / `EP_ERR:`，省去 OpenOCD 的逐字符日志回显与调试模式的临时文件往返。自测失败沿用原方式；socket 回复正确但收不到日志同步时，独立模式可启用，调试模式保留临时文件，避免无法排除的 GDB 广播。超时或断开的自测连接先丢弃并重连，迟到响应不会进入采样 FIFO。标记及纯 `EP_OK:` 回显不进入诊断尾部；错误处理保持原样。

宿主把 ELF 的可写且已分配节（`SHF_WRITE | SHF_ALLOC`）范围随采样计划传给 Worker，Worker 校验整数地址、32 位边界与范围数量。

普通读取允许合并不超过 32 字节的间隙。scatter 在一次 DAP run 内已可读取多个地址，只合并不超过 4 字节的间隙，以减少额外传输。两种路径都要求完整跨度落在同一节内。无节信息、跨节、外设或未知区域保持原读取方式。重叠、连续地址合并与 RAM 内字对齐扩读继续生效。

scatter 不支持或响应格式不兼容时，当轮使用普通读取计划。调试模式中重编译仍计入运行时对象已用的字节和读取组数。间隙只计实际吞吐与预算，单批上限为 1024 字节、8 组。

无回显自测和性能基准的复现方法见[采样与波形验证流程](../development/sampling-validation.md)。

## 自适应采样链路时钟

独立采样以 `init` 连接，各目标脚本的默认时钟通常偏保守。当两个适配器时钟设置均为 `0` 时，用户或 Agent 主动启动的独立采样会话在具有监视变量后可调优链路，Agent 主动发起的临时多次读取也可调优。会话创建时明确传入来源，其他会话默认关闭调优，包括调试、独立 RTT 和 Agent 单次读取。侧栏被动刷新仅枚举系统设备，时钟配置变化会停止独立采样，下一次显式启动才会应用新配置。

- **资格核对与基准读取**：先查询目标类型、传输协议与内存读取命令。确认是 `cortex_m` / `hla_target` 且使用 `swd` / `hla_swd` / `dapdirect_swd` 后，再查询当前频率和读取 CPUID（`0xE000ED00`）。若目标尚未完成 examine，则等待首轮完整成功采样后补测一次。限速采样以当前监视计划实测整帧读取耗时，校验用的 CPUID 读取不计入帧耗时。不限速采样和 Agent 临时多次读取仍以对齐 RAM 块（16–128 字，前后各校验一次 CPUID）做吞吐与完整性校验。无 RAM 范围或基准 RAM 读取失败时，改用纯 CPUID 多段或批量读取。
- **帧率目标**：限速时以波形物理读计划和波形周期试探，只有侧栏时使用侧栏读计划和 50 ms 周期。以目标周期的 85% 和实测平均读取耗时选择第一个达标档位，用该耗时设定起始间隔。目标未达到时按吞吐收益规则选频。限速模式、生效的帧率或主要读计划改变时重新评估。侧栏独有计划更新时沿用波形的截止时间和已验证时钟。运行中发生稳定性降速后沿用已验证的回退时钟。
- **分探针阶梯与停走规则**：按探针家族选择阶梯，只测试高于基线的挡位。资格查询、基准和候选挡位共用单调时钟截止时间，USB 等后端 600 ms，TCP 后端 1200 ms。每条 RPC 同时受单次超时和剩余预算约束。限时结束后停止试探，另有等长窗口用于重连和确认最终时钟。
  - **硬件/驱动钳制识别**：捕获 J-Link `Reduced speed from X kHz to Y kHz` 日志以及驱动返回的实际时钟。中间请求（如 ST-Link V3 的 12 MHz）映射为已测过的实际时钟（8 MHz）且尚未命中硬件上限时，跳过重复基准。触及硬件上限后结束试探，按已测结果选择时钟。
  - **平台期、减速与中点细化**：比较读取耗时的中位数。候选挡位相对于上一个已测实际挡位和当前最优挡位都至少降低 5% 且节省 0.15 ms，才按吞吐收益升频。连续两个挡位均未达到门槛时停止试探，选用已验证的较低时钟。若耗时比当前最优挡位高出 10% 以上（如 SWD WAIT），立即停止并恢复。某挡位被拒绝、读取失败、CPUID 不一致或 RPC 超时时，恢复当前最优时钟并尝试一次区间中点（500 kHz 步进）。
  - **试探误差隔离与运行中回退**：试探错误作废当前挡位。恢复时核对适配器返回的频率与 CPUID，重连失败或无法恢复已验证时钟时结束会话并报告故障。真实 USB/HID 传输丢失也立即结束会话。运行期间连续两轮读取失败或两次 `Polling failed` 后，降回前一已验证挡位，再次连续失败时降到基线，成功降速后重置吞吐和周期统计。
- **状态与授权边界**：`stats()` 与控制器状态新增 `adapterSpeedKhz`、`baseAdapterSpeedKhz` 与 `adaptiveSpeed` 供界面提示（波形速率提示显示 `SWD: N kHz`）与诊断脚本使用；写入授权身份（`writeConnectionIdentity`）与设置一致性校验仍只绑定用户配置值，不受运行期自适应调速影响。当前软件测试覆盖各探针阶梯、钳制、平台期、超时恢复与运行中降速模型，具体实板最终达到的链路时钟与吞吐仍需在目标硬件上实测。
- **波形设置控件同步**：波形窗口右上角绘图设置中的「采样时钟」卡片直接读写工作区 `emberprobe.samplingAdapterSpeedKhz`（开启自适应写 `0`，关闭写 1000–20000 kHz、步进 1000 kHz 的手动值）。采样进行中（含启动与停止过渡阶段），开关、滑条及宿主路由均锁定拒绝更改；停止采样后保留最近一次自适应选定频率用于展示与从该频率微调，更换探针/芯片或外部修改 `adapterSpeedKhz` 时清除该记忆。

## 连接仲裁

连续采样时，Tcl 连接可能只在两个事件循环轮次之间短暂空闲。采样会话采用 FIFO 仲裁，确保排队的读写请求能够在释放连接时取得所有权。

- 变量写入、单次读取、空闲等待按到达顺序排队；释放时所有权直接交给队首，采样轮次无法插队。
- 采样轮次只做非阻塞获取；有等待者时让出本轮。
- 超时仍返回 `PROBE_CONNECTION_BUSY_TIMEOUT`；停止或连接失败时立即拒绝排队者。

仲裁同样用于常规模式。

## 宿主流控

采样 Worker 每次向扩展宿主发送一个有上限的分片（≤256 批或约 256 KiB）并等待确认，其余批次留在 Worker 内排队。不限速时，若最早未送达的批次已排队 100 ms，或积压达到 1 MiB / 1024 批，Worker 暂停发起新的变量读取，积压送完后立即恢复，期间时间计入 `hostHoldMs`。固定频率采样不受宿主确认影响，详见 [波形历史设计](chart-history.md#数据流与竞态) 的积压预算。图表批次和逐样本时间戳保持原样；只有尚未送达的侧栏独有批次会合并为每个变量的最新值。

## 历史与归档

- 历史 Worker 的近期内存缓存每变量最多保留 360,001 点，且不超过 30 分钟。例如 2 kHz 的内存约覆盖 3 分钟；更早的点由磁盘归档提供，图表仍可查看从采样开始或上次清空以来的整个会话，预算计算与常规模式相同。
- 无历史 Worker 的回退路径同样按每变量 360,001 点裁剪。
- 磁盘归档以 `EPSA` v1 小端二进制日志 `samples.bin` 完整记录每批数据，通道键/身份字典只写一次，数值仅在文本精确往返时压缩。稳定字典下 1 / 3 / 10 个 f32 通道约 28 / 42 / 91 字节/行；默认 1 GiB 上限包含文件头和字典，耗尽后与常规模式一样报错并暂停采样。采样中工具栏的速率旁会在剩余不足 1 小时时显示「归档剩 mm:ss」（按最近约 10 秒的写入速度估算），剩余约 10 分钟与 1 分钟时各在状态栏提示一次；`emberprobe.samplingArchiveMaxMiB` 修改立即生效，调高后提示重新计时，已写满停止的采样也可重新开始（调低不会删除已写数据）。每约 64 KiB 的内存时间索引和字典快照让恢复从最近 30 分钟附近开始，再按完整记录边界追赶；CSV 继续读取完整归档，字段与输出格式不变。
- 历史视口请求至少相隔 80 ms，视口数据按像素列缩减并以类型化数组传输。绘图随视图及动画更新，请求、超采样与底图见 [波形历史与归档设计](chart-history.md)。

### 完整会话查看

完整会话查看由 Worker 的归档 LOD 索引支持：256 点 L0、每 16 桶一级，索引预算为内存历史配置的 25%
（默认 128 MiB）。长范围和底图使用摘要，放大旧范围时按需读原始行（每请求 16 MiB 上限，8 MiB 解码缓存）。
预算不足时最旧 L0 退为更粗摘要；`limited` 表示内存和归档均无法提供的数据，内存淘汰和索引变粗本身不再触发此标记。
冻结同时固定时间和归档字节截点，清空切换代次；“全部”、时间轴和底图覆盖全会话。归档结构和验证入口见 [波形历史设计](chart-history.md)。无历史 Worker 的回退路径仍受原内存上限约束。

## 验证边界

软件测试验证 scatter 计划、普通路径回退、自适应时钟、宿主流控和归档一致性。读写性能模型须区分请求路径、宿主处理与实板传输。相邻地址可以通过间隙合并减少请求，分散地址更依赖减少 DAP flush，连续块则受链路时钟和探针传输能力限制。

2026 年 10 月的历史实板对照仅覆盖 Windows 上的 APM32F407 + J-Link V9 和 STM32H750 + CMSIS-DAP v1。结果适用于对应原型、固件及连接条件。详细环境和结果保存在本地 `docs/records/validation/sampling-performance.md`。当前版本、其他探针及链路须在目标条件下另行验证。软件复现入口见[采样与波形验证流程](../development/sampling-validation.md)。
