# 探针选择与连接设计

用户行为见[探针连接](../guide/getting-started.md#探针连接)和 [J-Link](../guide/getting-started.md#j-link)。

## 选择优先级

按以下顺序解析探针。

1. 请求显式指定的 `probeSerial`。
2. 接口脚本指定的序列号。
3. 当前接口配置对应的工作区所选探针。
4. 唯一匹配的探针。存在多台同类探针时，尝试[按目标芯片区分](#自动模式与目标芯片校验)。

枚举按探针家族、VID/PID 和产品选择参数过滤。FTDI 通道及实际接口参数进入连接指纹，但多个通道只计为一台物理探针。通用 FTDI USB 串口芯片只有在接口脚本选择其 USB ID 时才列为探针。接口参数改变后，需重新选择工作区探针。

### 枚举不可用与设备缺席

系统查询不可用或未识别到匹配设备时，交由 OpenOCD 按接口脚本默认方式选择，并传入已指定的序列号。Linux 上个别 USB 设备的 sysfs 查询超时时，只跳过该设备并记录诊断。结果不完整时，保留已枚举的候选，将所选序列号交由 OpenOCD 核验。所有设备均无法读取时，视为枚举不可用。

### 后端与序列号

| 后端 | 规则 |
| --- | --- |
| J-Link | 保留十进制序列号及 Windows 驱动检查 |
| CMSIS-DAP、ST-Link、XDS110、Nu-Link、TI-ICDI | 共用唯一设备及精确序列号预检 |
| FTDI、FT232R、VSLLINK | 按脚本实际 USB ID 枚举；FTDI 须配置 VID/PID |
| KitProg | 后端无法执行序列号过滤，忽略已配置序列号，只允许一台匹配设备 |
| 其他 OpenOCD 适配器 | 直通 OpenOCD，显式序列号按 `adapter serial` 传入 |

Windows 设备实例尾串只是系统选择线索，不证明 USB 描述符原文。若真实序列号为 `ATK 20190528`，自动识别不能将 `ATK_20190528` 原样传给 OpenOCD。Windows 会把空格转为 `_`。唯一设备自动连接时省略序列号过滤；不含 `_` 的尾串按精确序列号用于点选的探针、侧栏列表及写入许可。用户显式配置的真实序列号可匹配其 Windows 别名，保留内部空格，作为单个 Tcl 参数传递。控制字符及 Tcl 元字符会被拒绝，J-Link 数字身份沿用原规则。

多台匹配设备并存时，选中的设备须有可用于 OpenOCD 过滤的序列号。无序列号设备或只有含 `_` 的 Windows 别名时，应断开其他匹配设备，或在接口脚本中配置真实 USB 序列号。无法消除歧义时返回 `PROBE_SELECTION_REQUIRED`，从界面发起的操作会展开调试器列表。确认所选设备缺席时，保留工作区记录并返回未连接状态。

## 自动模式与目标芯片校验

当请求未指定序列号、工作区也未固定探针时，按目标芯片识别连接。侧栏的「自动」按钮当前隐藏，自动解析仍适用于未固定探针的工作区。

读取芯片、故障读取、烧录、校验、调试和采样在各自的 OpenOCD 进程中，于 `init` 后、操作第一条命令前读取 CPUID、DBGMCU IDCODE 和 96 位 UID。校验本身不暂停、复位或写入目标。比较内核型号、DEV_ID 和 UID，跳过未读到的字段及修订版本。没有已知 DBGMCU 或 UID 地址的目标只比较 CPUID。任一已读字段与工作区记录不匹配时，通过 `shutdown error` 停止操作并返回 `PROBE_TARGET_MISMATCH`。侧栏显示记录芯片与当前芯片，用户可用「改用当前芯片」更新记录。

存在多台同类探针时，优先选择连接已记录芯片的设备。没有历史记录时，选择唯一一台连接匹配 STM32 系列的设备。先用已有读数，操作前校验可识别过期读数。缺少读数时并行短时连接各候选以识别芯片。Windows 下使用 SEGGER 驱动的 J-Link 无法读取时，返回 `PROBE_DRIVER_UNSUPPORTED` 并显示驱动提示。其他无法区分的情况返回 `PROBE_SELECTION_REQUIRED`，界面操作会展开设备列表。

固定的工作区设备、请求显式指定的序列号和外部 GDB 服务器连接均跳过此自动芯片校验。

## 工作区探针记录

工作区探针记录按本机保存在工作区内部状态（`mcu.selectedProbe`），不写入设置文件，也不覆盖用户设置。在列表中点选设备时记录接口脚本、序列号、探针类型、USB 设备 ID、来源 `user` 及实际接口配置指纹；在该设备上操作成功后刷新这条记录。独立操作通过显式序列号连接其他设备时，不替换侧栏选择。未点选时为自动模式，不记录探针：经过芯片校验的操作记录目标芯片（`source: "auto"`，见上文），其他成功操作只记录接口脚本（`source: "success"`），每次操作重新确认当前物理设备。旧版本的记录（v1、v2 及带序列号的 `success` 记录）保存的是最近一次连接的探针，读取时忽略其序列号和设备，因此这类工作区从自动模式开始。同时保留旧格式副本（`mcu.successfulProbeConnection`）供旧版本和已安装的 skill 读取；若旧版本之后在其中记录了另一台探针，也按同样方式读取。独立脚本使用相同决策规则，但没有工作区存储时不持久记忆。协议和速度覆盖项在 VS Code 插件设置中配置。写入授权绑定解析后的实际连接及接口配置。

## 枚举与“已连接调试器”列表

`probe.list` 只读取操作系统 USB 元数据；Windows 复合接口按物理父设备合并。无法读取的信息保持未知，不猜测序列号。能力检查使用 `noinit`，不会自动初始化目标。仅在用户主动选择 WinUSB 时才更改驱动；枚举、预检和硬件操作不会自动更改驱动。自定义接口脚本属于用户信任的代码，应避免在配置阶段显式操作硬件。

侧栏可见时，“选择调试器”下方的“已连接调试器”一行根据只读 USB 元数据列出所有已连接的调试器，与所选接口脚本无关。每次检测结束三秒后再次检测，连续五次无变化后放宽到十秒（macOS 枚举需启动 system_profiler，为十秒和三十秒）；点击刷新按钮或做任何选择都会立即检测。因此先配置再插入探针也会自动出现，无须重新选择调试器；Windows 尚未完成枚举时会在下次检测重试。切回保留的侧栏会立即补查，隐藏或关闭侧栏则停止轮询，过期检测结果不会覆盖新结果。这些检测不连接目标芯片，也不更改 USB 驱动。

主动刷新还会尝试读取各探针连接的芯片。可打开的探针各自使用短时 OpenOCD 会话，采用当前目标配置，不暂停、复位或写入目标。正在被 EmberProbe 或其他程序占用的探针不显示新读数。侧栏在序列号后显示内核型号，悬停提供完整芯片信息。

列表以对勾标记下次操作将使用的设备，依据包括工作区选择、唯一设备和目标芯片匹配。无法区分的设备仍列出，选择控件禁用并说明原因。自定义接口脚本自行选择设备时，列表只展示结果。所选设备断开后保留记录并显示「未连接」。

用户在侧栏选择不同家族的设备时切换到该家族的默认接口脚本，如 `jlink.cfg`、`cmsis-dap.cfg`、`stlink.cfg`、`xds110.cfg` 或 `nulink.cfg`。同一家族内保留当前脚本。Windows x64 下 J-Link 卡片可独立选择该设备的 USB 驱动，无法由内置助手校验的设备会显示原因。

Windows 下优先用内置只读 helper 枚举探针，避免每次操作都启动 PowerShell。

## 协议与时钟

已知 Cortex-M 目标默认 SWD，其他目标保留接口脚本默认协议；显式协议覆盖优先。OpenOCD 以 `noinit` 校验所选协议，只检查软件配置，不探测接线或探针能力，也不自动降速、切换协议或复位。

非零速度设置保留 target 原有复位事件及其时钟、看门狗和 Flash 初始化，只限制其中的 `adapter speed` 提速请求，保留低于上限的速度。除[烧录时钟](flash-and-debug.md#烧录时钟)所述的烧录时钟外，不自动重试或切换协议；在这些事件之外修改速度的自定义脚本仍属于用户信任的代码。

独立采样写入授权绑定配置的链路时钟以及原有探针身份。采样时钟设置变化使旧会话过期并停止，下一次显式启动应用新设置。工作区探针记录只保存探针选择信息，更换设备会清除波形中上次测得的频率。该设置可在 VS Code 中修改，Agent 配置快照只读提供它。

## Windows J-Link 驱动切换

驱动只在用户主动选择时更改。切换到 WinUSB 运行内置的未签名 helper，可能请求管理员授权；Windows 可能提示未知发布者或依本机策略阻止。helper 只更改受支持 J-Link USB 产品中已确认的调试接口，未知接口或驱动保持原样。切换前导出原驱动。若 J-Link 当前使用的已校验 SEGGER 驱动与备份记录的 `oemNN.inf` 不同（例如更新 SEGGER 软件后），或上次备份中途中断，下次切换到 WinUSB 时先把当前驱动导出到单独目录，完成后再替换备份及其记录；刷新中断时下次重做。

helper 固定校验配对 libwdi DLL 的 SHA-256，在加载提权代码前核对。发布流程核对两个原生文件及其在 VSIX 中字节的 SHA-256，这不证明发布者身份。缺少原生 helper 的开发构建在选择 WinUSB 时报错。Linux 使用 udev 权限，macOS 没有这一步。

重复切换到 WinUSB 时复用已准备的驱动包。下拉框保持加载状态，直到 OpenOCD 能打开所选接口；该检查不初始化 MCU。

驱动切换从枚举所选接口到验证结果持续持有 `ProbeCoordinator` 租约，与采样、RTT、调试、烧录、芯片读取和目标扫描互斥。侧栏在租约被占用期间禁用驱动下拉。若点击时状态尚未同步，后端仍会拒绝切换，侧栏会结束加载并显示原因。

侧栏选择探针或 OpenOCD 路径，以及 Agent 修改连接设置时，在异步枚举或校验之后、写入前重新检查会话状态。独立 RTT 持有租约时也禁止修改这些连接设置。

Windows 下因 SEGGER 驱动被阻止的操作还会显示 VS Code 右下角警告，提供“切换到 WinUSB”和“忽略（当前工作区不再提醒）”按钮。切换使用侧栏已有的驱动切换流程，但针对被阻止操作所解析的那台 J-Link，不再按设置重新解析，因此插有多台 J-Link 时同样可用；切换前会重新核对该设备的 USB 接口，设备已断开则不切换。完成后需手动重试原操作。在列表中选择的探针会立即记为当前工作区探针（即使操作随后因驱动失败），侧栏和后续操作使用同一台 J-Link。若 J-Link 被阻止但其接口无法通过切换校验（USB 型号不在已验证列表、调试接口不唯一、驱动提供者或 INF 无法验证），警告不提供切换按钮，而是说明原因，并把各接口的实例 ID、服务、驱动提供者和 INF 写入“EmberProbe 芯片信息”输出面板；此时需用 Zadig 等工具手动更换驱动。“忽略”保存在当前工作区，重新打开后仍有效，不影响其他工作区，也不绕过驱动检查或隐藏插件页面中的操作错误。仅关闭通知而未选择“忽略”时，下次操作仍会提醒；并发操作只显示一条待处理通知。

## 内置 Linux OpenOCD

部分系统 OpenOCD 0.12.0 构建在 CMSIS-DAP HID 后端匹配 `adapter serial` 时，会以
`*** buffer overflow detected ***: terminated` 崩溃。上游修复 e01e180f 纠正了宽字符转换的长度单位。
J-Link 不走这个后端，因此 J-Link 读取成功与此故障可以同时存在。仅凭版本字符串 `0.12.0`
不能判断系统发行包是否已回移植修复。

插件内置 Linux x64 的 xPack OpenOCD 0.12.0-7。路径为默认 `openocd` 或空值时，
连接硬件前自动离线解压并验证，之后复用扩展全局存储中按预置包 SHA-256 分隔的目录。
自动准备不改写设置或系统安装；包括 `/usr/bin/openocd` 在内的显式路径继续优先。
准备失败时停止操作，不回退到有缺陷的系统构建；侧栏提供路径选择和重新检查，内置运行时无需手动安装。
压缩包保留官方原始文件，并加入 [兼容配置](openocd-build.md)。上游基础包 SHA-256 为
`94b3790983beaf8ed57e646c0620dd66d705fddae03d290823a6ed3b439468d6`。
合入后的压缩包哈希及原始可执行文件哈希记录在 `resources/openocd-targets-manifest.json`。

原生崩溃报告为 `OPENOCD_NATIVE_CRASH`，不自动重试；单次读取诊断保留可执行路径、退出码、退出信号和有界原始日志。

## TCP 接口

采样连接使用预检解析的后端种类：`tcp`（CMSIS-DAP TCP / ST-Link TCP）的 Tcl RPC 超时为 5000 ms，其他后端仍为 2000 ms，超时报错仍是 `OPENOCD_RPC_TIMEOUT`。独立 TCP 采样在 `init` 后用 `info commands poll_interval` 守卫把目标后台轮询设为 500 ms（`poll_period` 只控制服务器主循环，不改变目标轮询）；当前随包 OpenOCD 尚无 `poll_interval`，保持默认 100 ms，较新的自定义 OpenOCD 才生效。调试模式不改轮询。持续轮询失败仍须至少 3 次且跨越 3000 ms 才锁定，500 ms 轮询下约 3 秒触发。

配置 TCP 主机但仍使用 `backend auto` 时返回 `PROBE_BACKEND_AMBIGUOUS`，避免自动切换 USB/TCP。两类 TCP 接口均跳过本机 USB 枚举，授权绑定端点、实际配置及显式序列号。主机和端口留在脚本中配置，不新增设置面板。

后端命令语义见 [OpenOCD 适配器文档](https://openocd.org/doc/html/Debug-Adapter-Configuration.html) 和 [ST-Link 后端实现](https://github.com/openocd-org/openocd/blob/master/src/jtag/drivers/stlink_usb.c)。

## 写入授权与连接身份

无序列号探针及自动选择的含 `_` Windows 别名，使用当前系统连接身份绑定待确认操作：Windows 最后接入时间、Linux USB 总线/地址及 sysfs inode/变更时间，或匹配的 macOS IORegistry entry ID。重新插拔后，即使端口或实例路径相同，原确认也会失效。无法读取连接身份（包括系统查询未找到匹配设备）时仍可检查设备，但固件下载、下载固件的调试启动、目标暂停/复位及内存写入返回 `PROBE_IDENTITY_UNVERIFIED`，配置准确 USB 序列号后即可使用；不下载固件的 attach 仍可使用。

这类探针的 Agent 内存写入仅提供 `once`，每次操作都须确认；既有 24 小时许可不能跳过确认。Flash 和外设写入沿用原有逐次确认。界面中的写入、下载、调试启动点击仍各自代表一次显式操作，不新增第二次审批弹窗。

写入确认绑定 ELF 与连接身份；工作区持久授权同样绑定连接，旧的仅绑定 ELF 的授权失效。外部 DAP 写入绑定调试会话与工作区。会话运行中更改连接设置后，旧会话禁止继续写入，须停止并重新启动；读取仍使用原连接。

## Agent 与命令行

- `config.get` 返回 `selectedProbe`。`probe.list` 只读取系统 USB 元数据，并用 `selected: true` 标记当前所选设备。
- Agent 按用户指定的设备，通过 `probe.select` 提交 `probe.list` 返回的准确设备 ID。MCP 入口为 `probe_select`，命令行入口为 `mcu-config --select-probe`。两者复用侧栏选择服务，重新核对设备是否连接、是否可区分及当前连接是否可编辑，再写入工作区记录。选择异族设备时，沿用侧栏更换默认接口脚本的规则。
- `config.set` 可更新 `adapterSpeedKhz`。烧录、校验脚本的显式序列号、速度和协议参数按单次操作解析。预检记录参数来源与错误，其职责限于检查连接配置。

## 探针通信失败与退出确认

Tcl 变量缺失、命令名或参数数量错误报告为 `OPENOCD_SCRIPT_ERROR`（`configuration`），
保留首个异常及最多五行、每行最多 500 字符的 `scriptError` 上下文；原始输出末八行仍留在
`openocdTail`。该诊断优先于后续通用 init、timeout、Flash 与 shutdown 错误，
但不覆盖明确的原生崩溃、USB 占用／权限／断开和探针通信失败；修正脚本前不可自动重试。

OpenOCD 的 `error writing data`、HID 读写失败、CMSIS-DAP 命令失败和 libusb IO/PIPE 错误统一报告为
`PROBE_COMMUNICATION_FAILED`（`probe_connection`）。明确的 busy、access、no-device 和原生崩溃仍优先；
通信错误优先于随后出现的 init、timeout、Flash 错误，保留操作阶段与有界原始日志。
通用 `failed to write` / `error writing` 仅在同一行明确包含 Flash 时归为 Flash 写入失败。
恢复需要先清理会话、确认进程退出或重新连接探针，不自动重试，也不自动复位 USB、切换驱动或解除写保护。

同一 provider 的 `ProbeCoordinator` 互斥芯片读取、下载、采样、Agent 临时读取、目标扫描和调试；
共享调试组持有一个租约，组内核复用服务器。临时 OpenOCD 操作在关闭后才释放租约，
采样、独立 RTT 及调试停止确认进程退出后释放；退出未确认则保留服务器和租约，用户可重试停止。
这不是跨 VS Code 窗口或跨应用的 USB 锁，进程退出也不能证明探针固件或 USB 端点恢复。
扩展宿主被强制终止时，不能承诺运行完正常的异步清理流程。

## 验证边界

软件测试覆盖 Windows、Linux 和 macOS 的枚举样例，以及身份选择、参数顺序、日志诊断、Worker 消息、授权绑定和 HIL 成功标记。随包 OpenOCD 的接口检查验证 Tcl 命令兼容性。真实驱动、固件和板卡的兼容性按 [HIL 流程](../../test/hil/README.md)分别验收，包括发布版 VSIX、Windows 10、复合接口 J-Link 和 Ozone 互操作。
