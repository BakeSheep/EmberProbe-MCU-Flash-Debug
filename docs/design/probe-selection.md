# 探针选择与连接设计

用户行为见[探针连接](../guide/getting-started.md#探针连接)和 [J-Link](../guide/getting-started.md#j-link)。

## 选择顺序

选择顺序为显式 `probeSerial`、接口脚本序列号、用户在侧栏为当前接口脚本点选的探针、当前唯一设备；同类型多台时由自动模式按目标芯片区分（见“自动模式与目标芯片校验”）。枚举按实际家族、VID/PID 和产品选择参数过滤。FTDI 通道及捕获到的接口参数进入连接指纹；不同通道不重复计算为物理 USB 探针。Windows 复合接口按物理父设备合并。系统查询不可用或未识别到匹配设备时，由 OpenOCD 按接口脚本默认方式选择；点选设备的序列号仍会传入。Linux 下若某个 USB 设备（例如调试中目标板自身的 USB 设备，内核正在重试）在查询时限内无法读取 sysfs 信息，只跳过该设备并在连接诊断中注明，不再使整份枚举失效；已读到的探针照常选择，但被跳过的设备可能正是所选探针，因此不再据此判定序列号缺席，而是把序列号交给 OpenOCD 校验。所有设备都无法读取时视为枚举不可用。接口参数改变后，之前的点选不再使用，需在侧栏列表中重新点选。通用 FTDI USB 串口芯片仅在接口脚本选择其 USB ID 时列为探针。

| 后端 | 规则 |
| --- | --- |
| J-Link | 保留十进制序列号及 Windows 驱动检查 |
| CMSIS-DAP、ST-Link、XDS110、Nu-Link、TI-ICDI | 共用唯一设备及精确序列号预检 |
| FTDI、FT232R、VSLLINK | 按脚本实际 USB ID 枚举；FTDI 须配置 VID/PID |
| KitProg | 后端无法执行序列号过滤，忽略已配置序列号，只允许一台匹配设备 |
| 其他 OpenOCD 适配器 | 直通 OpenOCD，显式序列号按 `adapter serial` 传入 |

Windows 设备实例尾串只是系统选择线索，不证明 USB 描述符原文。若真实序列号为 `ATK 20190528`，自动识别不能将 `ATK_20190528` 原样传给 OpenOCD。Windows 会把空格转为 `_`。唯一设备自动连接时省略序列号过滤；不含 `_` 的尾串按精确序列号用于点选的探针、侧栏列表及写入许可。用户显式配置的真实序列号可匹配其 Windows 别名，保留内部空格，作为单个 Tcl 参数传递。控制字符及 Tcl 元字符会被拒绝，J-Link 数字身份沿用原规则。

多台匹配设备并存时，OpenOCD 必须能够执行选择。具有可用序列号（含不带 `_` 的 Windows 别名）的设备可在侧栏列表中点选；无法确定时操作以 `PROBE_SELECTION_REQUIRED` 停止，从界面发起的操作会展开该列表，而不是弹出选择框。无序列号设备或含 `_` 的 Windows 别名不能安全区分多台探针，应断开其他设备或在接口脚本中显式填写真实 USB 序列号。点选的设备缺席时不自动替换。记录按第三版写入；旧记录读取时忽略其中的探针（见 [J-Link](../guide/getting-started.md#j-link)）。未点选时只记录接口脚本，下次重新解析物理设备。

## 自动模式与目标芯片校验

“自动”按钮暂时隐藏；未固定探针时仍保留下述行为。自动模式（请求未显式指定序列号、未固定探针）跟随目标芯片，而不是固定某台探针。它发起的每个操作（读取芯片、故障读取、烧录、校验、调试、采样）都在本操作自己的 OpenOCD 进程中，于 `init` 之后立即读取 CPUID、目标的 DBGMCU IDCODE 及 96 位 UID，耗时 2–6 ms，不暂停、不复位、不写入目标。读到的字段与工作区为当前目标配置记录的芯片不同时，OpenOCD 在操作的第一条命令之前以 `shutdown error` 结束，操作报告 `PROBE_TARGET_MISMATCH`；读不到的字段不算不一致；芯片修订版本（CPUID 的 variant/revision、IDCODE 的 REV_ID）不参与比较，只比较内核型号、DEV_ID 与 UID。操作成功后记录本次读到的芯片（工作区状态 `mcu.selectedProbe`，`source: "auto"`，含 `target` 与 `chip`），不记录探针序列号，因此保持自动模式。侧栏显示正在校验的芯片；发生不一致后显示两颗芯片及“改用当前芯片”，点击后记录当前芯片。配置类型的探针有多台时，自动模式选用连接着已记录芯片的那台；尚无记录时，选用唯一一台芯片属于所配置 STM32 系列的探针。优先使用之前的读数，读数过期由操作自身的校验发现；否则用简短会话（init、三项读取、shutdown）同时读取所有候选探针。Windows 下使用 SEGGER 驱动的 J-Link 无法读取；因此无法确定时，操作以该探针的 `PROBE_DRIVER_UNSUPPORTED` 停止并给出驱动提醒，同时展开侧栏列表，可在其卡片的下拉中切换驱动。其他无法确定的情况以 `PROBE_SELECTION_REQUIRED` 停止；从界面发起的操作会展开侧栏列表，列表中显示每台探针的芯片，由用户点选。侧栏固定的探针或独立请求显式指定的序列号按指定使用，不做校验。外部 GDB 服务器会话使用 EmberProbe 之外启动的服务器，不做校验。没有已知 DBGMCU/UID 地址的目标只比较 CPUID。

## 工作区探针记录

工作区探针记录按本机保存在工作区内部状态（`mcu.selectedProbe`），不写入设置文件，也不覆盖用户设置。在列表中点选设备时记录接口脚本、序列号、探针类型、USB 设备 ID、来源 `user` 及实际接口配置指纹；在该设备上操作成功后刷新这条记录。独立操作通过显式序列号连接其他设备时，不替换侧栏选择。未点选时为自动模式，不记录探针：经过芯片校验的操作记录目标芯片（`source: "auto"`，见上文），其他成功操作只记录接口脚本（`source: "success"`），每次操作重新确认当前物理设备。旧版本的记录（v1、v2 及带序列号的 `success` 记录）保存的是最近一次连接的探针，读取时忽略其序列号和设备，因此这类工作区从自动模式开始。同时保留旧格式副本（`mcu.successfulProbeConnection`）供旧版本和已安装的 skill 读取；若旧版本之后在其中记录了另一台探针，也按同样方式读取。独立脚本使用相同决策规则，但没有工作区存储时不持久记忆。工作区探针在侧栏选择，协议和速度覆盖项在 VS Code 插件设置中配置。写入授权绑定解析后的实际连接及接口配置。

## 枚举与“已连接调试器”列表

`probe.list` 只读取操作系统 USB 元数据；Windows 复合接口按物理父设备合并。无法读取的信息保持未知，不猜测序列号。能力检查使用 `noinit`，不会自动初始化目标。仅在用户主动选择 WinUSB 时才更改驱动；枚举、预检和硬件操作不会自动更改驱动。自定义接口脚本属于用户信任的代码，应避免在配置阶段显式操作硬件。

侧栏可见时，“选择调试器”下方的“已连接调试器”一行根据只读 USB 元数据列出所有已连接的调试器，与所选接口脚本无关。每次检测结束三秒后再次检测，连续五次无变化后放宽到十秒（macOS 枚举需启动 system_profiler，为十秒和三十秒）；点击刷新按钮或做任何选择都会立即检测。因此先配置再插入探针也会自动出现，无须重新选择调试器；Windows 尚未完成枚举时会在下次检测重试。切回保留的侧栏会立即补查，隐藏或关闭侧栏则停止轮询，过期检测结果不会覆盖新结果。这些检测不连接目标芯片，也不更改 USB 驱动。

刷新按钮还会读取列表中每台可打开探针所连接的目标芯片（每台一个简短 OpenOCD 会话，同时进行，使用该探针的接口脚本与所选目标配置；不暂停、不复位、不写入），在序列号之后显示其内核型号（如 `Cortex-M4`），悬停可查看完整芯片信息。EmberProbe 有操作占用探针时不读取，正在使用的探针在操作结束前不显示芯片；被其他程序占用的探针无法打开，同样不显示。列表以对勾标出下一次操作将使用的设备，悬停可查看依据（已选择的设备、唯一设备、按目标芯片选择）。点选某台设备后，它会保存为工作区所选探针。若所选设备与当前接口脚本不是同一类型，“选择调试器”会同时改为该类型的默认脚本（`jlink.cfg`、`cmsis-dap.cfg`、`stlink.cfg`、`xds110.cfg` 或 `nulink.cfg`）；同类型的其他脚本（如 `stlink-v2.cfg`）保持不变；卡片的悬停提示会事先注明将切换到的脚本，切换时该行原地更新，不重新加载侧栏，也不弹出通知。“自动”按钮暂时隐藏，手动点选探针与刷新功能保留；已有的自动选择逻辑仍保留（见上文）。已保存的设备被拔出后仍保持选中，并显示为“未连接”，不会改用其他设备。从界面发起的操作无法确定探针或所选设备已拔出时，会展开此列表而不是弹出选择框；探针只在此处选择。OpenOCD 无法区分的设备（同类型多台且没有可靠 USB 序列号）会列出但不可选，并说明原因。自定义接口脚本自行选择设备时，该行只显示结果。Windows x64 下，每台 J-Link 的卡片都有自己的 WinUSB/SEGGER 驱动下拉，无需先选中即可切换它的驱动，自动模式下也是如此。helper 无法校验的 J-Link 在其卡片上显示“驱动需手动处理”，悬停可查看原因。Agent 看到的是同一选择：`config.get` 返回 `selectedProbe`，`probe.list` 用 `selected: true` 标出该设备；Agent 不能修改这一选择。

Windows 下优先用内置只读 helper 枚举探针，避免每次操作都启动 PowerShell。

## 协议与时钟

已知 Cortex-M 目标默认 SWD，其他目标保留接口脚本默认协议；显式协议覆盖优先。OpenOCD 以 `noinit` 校验所选协议，只检查软件配置，不探测接线或探针能力，也不自动降速、切换协议或复位。

非零速度设置保留 target 原有复位事件及其时钟、看门狗和 Flash 初始化，只限制其中的 `adapter speed` 提速请求，保留低于上限的速度。除[烧录时钟](flash-and-debug.md#烧录时钟)所述的烧录时钟外，不自动重试或切换协议；在这些事件之外修改速度的自定义脚本仍属于用户信任的代码。

独立采样写入授权绑定实际生效的链路时钟以及原有探针身份；设置变化使旧采样会话过期并重连，工作区探针记录仍只保存探针选择信息。该设置可在 VS Code 中修改，Agent 配置快照只读提供它，不新增 MCP/Agent 修改参数。

## Windows J-Link 驱动切换

驱动只在用户主动选择时更改。切换到 WinUSB 运行内置的未签名 helper，可能请求管理员授权；Windows 可能提示未知发布者或依本机策略阻止。helper 只更改受支持 J-Link USB 产品中已确认的调试接口，未知接口或驱动保持原样。切换前导出原驱动。若 J-Link 当前使用的已校验 SEGGER 驱动与备份记录的 `oemNN.inf` 不同（例如更新 SEGGER 软件后），或上次备份中途中断，下次切换到 WinUSB 时先把当前驱动导出到单独目录，完成后再替换备份及其记录；刷新中断时下次重做。

helper 固定校验配对 libwdi DLL 的 SHA-256，在加载提权代码前核对。发布流程核对两个原生文件及其在 VSIX 中字节的 SHA-256，这不证明发布者身份。缺少原生 helper 的开发构建在选择 WinUSB 时报错。Linux 使用 udev 权限，macOS 没有这一步。

重复切换到 WinUSB 时复用已准备的驱动包。下拉框保持加载状态，直到 OpenOCD 能打开所选接口；该检查不初始化 MCU。

Windows 下因 SEGGER 驱动被阻止的操作还会显示 VS Code 右下角警告，提供“切换到 WinUSB”和“忽略（当前工作区不再提醒）”按钮。切换使用侧栏已有的驱动切换流程，但针对被阻止操作所解析的那台 J-Link，不再按设置重新解析，因此插有多台 J-Link 时同样可用；切换前会重新核对该设备的 USB 接口，设备已断开则不切换。完成后需手动重试原操作。在列表中选择的探针会立即记为当前工作区探针（即使操作随后因驱动失败），侧栏和后续操作使用同一台 J-Link。若 J-Link 被阻止但其接口无法通过切换校验（USB 型号不在已验证列表、调试接口不唯一、驱动提供者或 INF 无法验证），警告不提供切换按钮，而是说明原因，并把各接口的实例 ID、服务、驱动提供者和 INF 写入“EmberProbe 芯片信息”输出面板；此时需用 Zadig 等工具手动更换驱动。“忽略”保存在当前工作区，重新打开后仍有效，不影响其他工作区，也不绕过驱动检查或隐藏插件页面中的操作错误。仅关闭通知而未选择“忽略”时，下次操作仍会提醒；并发操作只显示一条待处理通知。

## 内置 Linux OpenOCD

`*** buffer overflow detected ***: terminated` 崩溃。上游修复 e01e180f 纠正了宽字符转换的长度单位。
J-Link 不走这个后端，因此 J-Link 读取成功与此故障可以同时存在。仅凭版本字符串 `0.12.0`

插件内置 Linux x64 的 xPack OpenOCD 0.12.0-7。路径为默认 `openocd` 或空值时，
连接硬件前自动离线解压并验证，之后复用扩展全局存储中按预置包 SHA-256 分隔的目录。

准备失败时停止操作，不回退到有缺陷的系统构建；侧栏提供路径选择和重新检查，内置运行时无需手动安装。
压缩包保留官方原始文件，并加入 [兼容配置](openocd-build.md)。上游基础包 SHA-256 为
`94b3790983beaf8ed57e646c0620dd66d705fddae03d290823a6ed3b439468d6`。

原生崩溃报告为 `OPENOCD_NATIVE_CRASH`，不自动重试；单次读取诊断保留可执行路径、退出码、退出信号和有界原始日志。复现与验证范围见 [Linux CMSIS-DAP 诊断记录](../records/diagnostics/2026-10-08-linux-cmsis-dap.md)。

## TCP 接口

采样连接使用预检解析的后端种类：`tcp`（CMSIS-DAP TCP / ST-Link TCP）的 Tcl RPC 超时为 5000 ms，其他后端仍为 2000 ms，超时报错仍是 `OPENOCD_RPC_TIMEOUT`。独立 TCP 采样在 `init` 后用 `info commands poll_interval` 守卫把目标后台轮询设为 500 ms（`poll_period` 只控制服务器主循环，不改变目标轮询）；当前随包 OpenOCD 尚无 `poll_interval`，保持默认 100 ms，较新的自定义 OpenOCD 才生效。调试模式不改轮询。持续轮询失败仍须至少 3 次且跨越 3000 ms 才锁定，500 ms 轮询下约 3 秒触发。

配置 TCP 主机但仍使用 `backend auto` 时返回 `PROBE_BACKEND_AMBIGUOUS`，避免自动切换 USB/TCP。两类 TCP 接口均跳过本机 USB 枚举，授权绑定端点、实际配置及显式序列号。主机和端口留在脚本中配置，不新增设置面板。

后端命令语义见 [OpenOCD 适配器文档](https://openocd.org/doc/html/Debug-Adapter-Configuration.html) 和 [ST-Link 后端实现](https://github.com/openocd-org/openocd/blob/master/src/jtag/drivers/stlink_usb.c)。

## 写入授权与连接身份

无序列号探针及自动选择的含 `_` Windows 别名，使用当前系统连接身份绑定待确认操作：Windows 最后接入时间、Linux USB 总线/地址及 sysfs inode/变更时间，或匹配的 macOS IORegistry entry ID。重新插拔后，即使端口或实例路径相同，原确认也会失效。无法读取连接身份（包括系统查询未找到匹配设备）时仍可检查设备，但固件下载、下载固件的调试启动、目标暂停/复位及内存写入返回 `PROBE_IDENTITY_UNVERIFIED`，配置准确 USB 序列号后即可使用；不下载固件的 attach 仍可使用。

这类探针的 Agent 内存写入仅提供 `once`，每次操作都须确认；既有 24 小时许可不能跳过确认。Flash 和外设写入沿用原有逐次确认。界面中的写入、下载、调试启动点击仍各自代表一次显式操作，不新增第二次审批弹窗。

写入确认绑定 ELF 与连接身份；工作区持久授权同样绑定连接，旧的仅绑定 ELF 的授权失效。外部 DAP 写入绑定调试会话与工作区。会话运行中更改连接设置后，旧会话禁止继续写入，须停止并重新启动；读取仍使用原连接。

## Agent 与命令行

`config.get` 返回 `selectedProbe`；`config.set` 支持 `adapterSpeedKhz`，不能选择探针，请在侧栏选择工作区设备。烧录、校验脚本支持上述显式序列号、速度和协议参数。预检记录参数来源与错误，不安装或替换 USB 驱动。

`probe.list` 只读取操作系统 USB 元数据。`config.get` 返回 `selectedProbe`，`probe.list` 用 `selected: true` 标出该设备；Agent 不能修改这一选择。

## 验证边界

软件测试覆盖各系统枚举样例、接口解析、设备选择及授权失效；随包 OpenOCD 的接口检查验证 Tcl 命令兼容性。这些检查不证明真机支持，硬件结果须按 [HIL 流程](../../test/hil/README.md) 单独记录。

软件测试覆盖三类系统的枚举样例、身份选择、参数顺序、原生日志诊断、Worker 传递、授权绑定和 HIL 成功标记，但不认证真实驱动或固件。发布版 VSIX 的真机验证、Windows 10、复合接口 J-Link 和 Ozone 互操作仍须按专用板 HIL 流程验收。
