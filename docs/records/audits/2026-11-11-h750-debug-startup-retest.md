# H750_RttTest 调试启动修复复测（2026-11-11）

使用本地构建的 EmberProbe 扩展开发宿主，在 Windows、VS Code 1.145.2 上打开原 H750_RttTest 工作区。仍用原选中的 `H750_RttTest-nosym.elf`、STM32H750 和 CMSIS-DAP，工作区未绑定 SVD。每个成功的复位调试样本停在 `main`，然后停止调试。临时 F5 配置开启 `performanceTrace`。

原始样本见 [修复前真机审计](2026-11-11-h750-debug-startup.md)。各重载样本约在执行窗口重载 11 秒后按 F5。完整配置档中，最终构建在按键后 31.758 秒记录 `onDebugResolve`。停用其他已安装扩展后，等待降到 0.512 秒。隔离试验同时改变了加载的扩展组合，具体阻塞点尚未定位到单个扩展。两次调试的下载与校验分别为 3.568 秒和 3.544 秒。

完整配置档的早期重复试次出现 CMSIS-DAP 通信失败，隔离配置的首次尝试也未建立 OpenOCD 连接。用户重新插拔探针 USB 后，隔离配置与重新打开的完整配置档均成功到达 `main`。表中只列成功到达 `main` 的耗时。
