# RTT J-Link board validation — 2026-11-06

Validation of the `feat/rtt-logging` extension flow over J-Link, and an A/B comparison of the
`0005-emberprobe-rtt-drain.patch` OpenOCD against the same bundled build without it.

## Setup

- Windows x64, OS build 10.0.26300; isolated VS Code 1.136.1 Extension Host.
- STM32H750 with J-Link V9 (HW 9.70, firmware of 2021-05-07, serial 20781318, WinUSB); SWD at 4 MHz unless stated.
- Firmware `STM32Project/H750_RttTest`, preset Debug (control block in DTCM, 0x200041a4).
- Patched: `resources/openocd-win32-x64.tar.gz` of this branch. Base: the same file from `master`.

## Results

`--suite rtt` with the patched build: 41 of 41 steps passed, including start and stop, input, Agent, MCP, skill,
following chip read, sampling, debug and flash, soft reset, and every control block location path.

The stress suite then ran for the first time, because `smoke-profile.js` had dropped `checks.rtt.stress`. All six stress steps at
96000 B/s passed on both builds. Its two setup defects are fixed: it raced the debug entry stop, and it read the chart
rate instead of the sidebar rate.

Sustained 96000 B/s through the extension, 3 s:

| Context, polling      | Mode  | Patched   | Base      | Loss                              |
| --------------------- | ----- | --------- | --------- | --------------------------------- |
| Own session, 100 ms   | skip  | 8.8 kB/s  | 8.8 kB/s  | Target rejects bytes, as expected |
| Own session, 10 ms    | skip  | 60.9 kB/s | 60.9 kB/s | Target rejects bytes, as expected |
| Sampling, 10 ms       | trim  | 72.7 kB/s | 72.5 kB/s | Target rejects bytes, as expected |
| Running debug, 100 ms | block | 9.1 kB/s  | 9.2 kB/s  | None; firmware is throttled       |
| Running debug, 10 ms  | block | 63.1 kB/s | 60.8 kB/s | None; firmware is throttled       |

At 8000 B/s every run received all bytes. Sampling kept its 20 Hz sidebar rate with no missed deadlines on both builds.

12 MHz through the extension gave the same results: 8.8 kB/s at 100 ms and about 60 kB/s at 10 ms on both builds.

Raw OpenOCD at 300000 B/s, without the extension:

| SWD clock | Polling | Patched    | Base       |
| --------- | ------- | ---------- | ---------- |
| 4 MHz     | 1 ms    | 115.9 kB/s | 116.0 kB/s |
| 12 MHz    | 1 ms    | not run    | 148.1 kB/s |
| 12 MHz    | 10 ms   | not run    | 85.3 kB/s  |
| 12 MHz    | 100 ms  | not run    | 9.9 kB/s   |

The patched 12 MHz raw runs did not start, because the probe timed out after the previous OpenOCD was killed.

## Findings

- One poll of two channels costs about 7.8 ms at 4 MHz and 5.9 ms at 12 MHz, so a poll on this probe always outlasts
  the patch's 5 ms budget. It never reads a second block here, which matches the identical A/B results.
- The clock changes the result little because the cost is mostly USB round trips.
- The practical limit here is the polling interval. Lowering it from 10 ms to 1 ms nearly doubles raw throughput on
  either build.

## Outcome

`0005-emberprobe-rtt-drain.patch` was removed after these results, and the bundled OpenOCD stays the `master` build.

## Probe

Before the runs, the J-Link failed with SWD `JUNK` acks after DPIDR and then USB errors, and briefly left the system.
It recovered after a replug and several seconds of further drop-outs, then stayed stable through all suite runs. The
cause is unknown. It is not related to RTT, because the failure came before `init` completed.
