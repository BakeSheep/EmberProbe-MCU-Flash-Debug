# 调试性能优化与验证

范围：EmberProbe 原生 DAP 适配器与共享调试服务、侧栏。Cortex-Debug 仓库未修改；共享写入服务对两种适配器运行同一套回归。

## 已实施

| 瓶颈 | 实现与边界 |
| --- | --- |
| 暂停等待无关只读请求 | 运行态 pause 直接发送 MI interrupt；已经排队的 continue 之后收到 pause 时仍保持先继续再暂停的语义。 |
| 单步排在大批变量刷新之后 | 控制请求优先于同一段队列中的只读请求；正在执行的读取在 MI 边界检查取消。写入、断点修改和会话启动保持顺序。 |
| 控制命令前串行删除所有 varobj | 立即使本地引用失效，延后 GDB 删除。清理每次一条并让出事件循环；运行、控制或前台请求处理期间暂停清理，结束会话后丢弃队列。 |
| 逐变量重选线程和帧 | 变量页共享上下文，同一已选帧复用；STL 换帧、栈查询、运行、线程退出和写入使相应缓存更新或失效。 |
| 相同悬停不断创建 varobj | 同一停点、线程、帧、表达式复用普通标量 varobj；写入与执行状态变化清空缓存。STL 和动态对象仍走完整路径。 |
| 无变化断点更新仍暂停目标 | 相同位置与条件直接返回既有 DAP 断点；有变化才执行原来的中断与增删流程。 |
| 外设逐寄存器读取 | 合并同一外设内同宽、连续、对齐、无读副作用的请求，最大 4096 字节；不跨空洞。视图批读失败按寄存器降级，保留各自错误。 |
| 自动视图抢占停点首屏 | 自动刷新延后 150ms，折叠面板不读硬件；运行、折叠或新停点取消旧计时器。RTOS 面板展开时，每次暂停自动刷新任务与栈填充扫描结果；手动刷新也包含栈扫描。 |
| 写入重复读相邻字节 | 全对齐写跳过 read-modify-write 的额外读；输入顺序相邻的对齐块合并，最大 4096 字节。仍进行写前快照与写后校验；非对齐写保留邻字节保护。 |
| 断点列表查询串行 IPC | 最多 8 个并发查询，输出保留原列表顺序，每个错误独立处理。 |

未知内存别名和 PC/SP 修改仍采用保守的整体变量失效；不会为了速度保留可能错误的地址或旧引用。批量写降低了对应失效事件数量，独立写入仍各自通知客户端。

## 性能回归门禁

`node test/debug-performance.test.js` 使用可控 Promise 阻塞与命令计数，不依赖机器计时精度或真实探针：

| 场景 | 审计基线 | 优化后验证 |
| --- | --- | --- |
| 100 个普通局部变量 | 403 条 MI | 203 条 MI，线程/帧各选一次 |
| 20 次相同标量悬停 | 20 个 varobj | 1 个 varobj，后续求值复用 |
| 100 个 varobj 后继续/单步 | 执行前 100 次删除 | 执行前 0 次删除 |
| 相同断点配置、目标运行中 | interrupt + continue | 0 条 MI |
| 64 个安全连续寄存器 | 64 次单寄存器读取 | 服务层 1 次 256 字节读取；UI 32 项分块时为 2 次 |
| 两个相邻 4 字节 RAM 写入 | 4 读 + 2 写 | 2 读 + 1 写，保留前后校验 |

配套测试覆盖 RTOS 暂停自动栈扫描、显式关闭扫描的轻量快照、折叠视图不读硬件、缓存换帧、写入不可抢占、恢复运行时停止后台删除、Cortex-Debug/EmberProbe 共享写入兼容和外设读失败隔离。

## 诊断与实际测量

在原生调试的 launch 或 attach 配置增加 `"performanceTrace": true`。Debug Console 输出请求名、排队毫秒、执行毫秒、MI 命令数及取消状态；不输出表达式、地址或数据。默认关闭。

命令计数减少不等于真实硬件的固定延迟收益。真板复测应使用同一固件、探针、SWD 频率和变量展开状态，分别记录 pause、continue、next、stepIn、stepOut、restart 的请求到 stopped，以及栈/变量首屏完成时间；对比至少 30 次的中位数和 P95。

暂停不会强行终止 GDB 正在执行的同步目标操作；单步抢占也要等待已经发出的单条 MI 命令返回。长时间失联仍由原有超时与终止通道处理。此次未运行破坏性 HIL 测试。
